Вопросы по 1С-Битрикс

Раздел охватывает ключевые темы: архитектуру ядра, ORM D7, инфоблоки, кэширование, компоненты, события, безопасность.

1. Архитектура ядра​

Чем D7 отличается от старого ядра?​

Старое ядро работает через глобальные классы с префиксом C (CUser, CIBlockElement, CFile). Нет пространств имён, нет автозагрузки. Методы возвращают CDBResult, данные вытягиваются через Fetch().

D7 — объектно-ориентированное ядро с пространствами имён (\Bitrix\Main\...), автозагрузкой по PSR-4 и паттерном DataManager. Каждая таблица — класс-наследник DataManager с именем *Table. Ошибки возвращаются через объект Result, а не через false.

// Старое ядро
$res = CUser::GetList($by, $order, ['ACTIVE' => 'Y']);
while ($ar = $res->Fetch()) { ... }

// D7
$res = \Bitrix\Main\UserTable::getList(['filter' => ['=ACTIVE' => 'Y']]);
while ($row = $res->fetch()) { ... }

Зачем уходить от GET/_GET/G​ET/_POST и global $APPLICATION?​

$_GET/$_POST — нетипизированные суперглобальные массивы. Их прямое использование усложняет тестирование и создаёт риски XSS. global $APPLICATION — глобальное состояние, скрытая зависимость.

D7-альтернатива:

$request = \Bitrix\Main\Application::getInstance()->getContext()->getRequest();
$id = (int) $request->getQuery('ID');

Request — объект с явным контрактом, передаётся как зависимость, мокируется в тестах.

Как работает автозагрузка в D7?​

Битрикс регистрирует маппинг «имя класса → путь к файлу». При первом обращении к классу файл подключается автоматически.

Для ядра: \Bitrix\Main\UserTable → bitrix/modules/main/lib/usertable.php.

Для собственных классов:

\Bitrix\Main\Loader::registerAutoLoadClasses(null, [
    'MyNamespace\MyClass' => '/local/php_interface/classes/MyClass.php',
]);

2. ORM D7 и база данных​

Какие ключи принимает getList()?​

select, filter, order, limit, offset, group, runtime, cache.

SomeTable::getList([
    'select'  => ['ID', 'NAME'],
    'filter'  => ['=ACTIVE' => 'Y'],
    'order'   => ['SORT' => 'ASC'],
    'limit'   => 20,
    'offset'  => 40,
    'cache'   => ['ttl' => 3600],
]);

Как сделать фильтрацию с логикой OR?​

'filter' => [
    'LOGIC' => 'OR',
    ['=STATUS' => 'new'],
    ['=STATUS' => 'pending'],
]

Что такое ExpressionField и когда его использовать?​

ExpressionField добавляет произвольное SQL-выражение в запрос: COUNT, SUM, CONCAT, арифметика. Используется когда нужно агрегировать данные или вычислить значение на уровне SQL.

use Bitrix\Main\ORM\Fields\ExpressionField;

SomeTable::getList([
    'select'  => ['USER_ID', 'ORDER_COUNT' => 'CNT'],
    'runtime' => [
        new ExpressionField('CNT', 'COUNT(%s)', ['ID']),
    ],
    'group' => ['USER_ID'],
]);

Как сделать JOIN в D7?​

Через ReferenceField в getMap() таблицы или через runtime в запросе:

use Bitrix\Main\ORM\Fields\Relations\ReferenceField;
use Bitrix\Main\ORM\Query\Join;

SomeTable::getList([
    'select'  => ['ID', 'USER_NAME' => 'USER.NAME'],
    'runtime' => [
        new ReferenceField(
            'USER',
            \Bitrix\Main\UserTable::class,
            Join::on('this.USER_ID', 'ref.ID'),
            ['join_type' => 'LEFT']
        ),
    ],
]);

Как обработать ошибки после add()/update()?​

$result = SomeTable::add(['NAME' => 'Test']);

if ($result->isSuccess()) {
    $id = $result->getId();
} else {
    $errors = $result->getErrorMessages(); // Массив строк
}

Чем fetch() отличается от fetchAll()?​

fetch() возвращает одну строку за вызов, данные не накапливаются в памяти — потребление O(1). fetchAll() возвращает весь результат сразу — O(N) памяти. При больших выборках используйте fetch() в цикле.

3. Инфоблоки и каталог​

Какие основные таблицы использует инфоблок?​

ТаблицаСодержимое
b_iblockМетаданные инфоблоков
b_iblock_elementОсновные поля элементов
b_iblock_propertyОписание свойств
b_iblock_element_propertyЗначения свойств (тип хранения 1.0)
b_iblock_element_prop_sXЗначения свойств (тип хранения 2.0)

В чём разница между типом хранения 1.0 и 2.0?​

1.0: каждое значение каждого свойства — отдельная строка в b_iblock_element_property. Один элемент с 20 свойствами — 20 строк. JOIN медленнее при росте данных.

2.0: создаётся отдельная таблица b_iblock_element_prop_sX (X — ID инфоблока). Все свойства элемента — в одной строке, каждое свойство — отдельный столбец. Выборка быстрее, но добавление нового свойства требует ALTER TABLE.

Почему CIBlockElement::GetList актуальнее D7 ElementTable для инфоблоков?​

ElementTable работает только со стандартными полями (NAME, CODE, SORT...). Значения свойств, типы «Цена», «Файл», «Список», множественные свойства, связи с каталогом — всё это нативно поддерживается только в старом API. Стандартные компоненты каталога, новостей, поиска написаны под CIBlockElement.

Что такое фасетный индекс?​

Дополнительная плоская таблица с предвычисленными данными для фильтрации в каталоге. Без неё каждый клик по фильтру — тяжёлый SQL с JOIN по EAV-таблицам. С индексом — быстрый SELECT по плоской таблице. Включается в настройках инфоблока, обновляется автоматически при изменении элементов или вручную через \Bitrix\Iblock\PropertyIndex\Manager::updateIndex($iblockId).

4. Кэширование​

Чем Unmanaged Cache отличается от Managed Cache?​

Unmanaged (CPHPCache, \Bitrix\Main\Data\Cache): кэш с фиксированным TTL. Инвалидация только по истечении времени. Не знает об изменениях в данных.

Managed (управляемый): Битрикс автоматически инвалидирует кэш при изменении связанных данных через API. Используется в D7 ORM при указании 'cache' => ['ttl' => ...].

Как работает тегированный кэш?​

При записи в кэш регистрируются теги. При изменении данных вызывается clearByTag() — все записи с этим тегом удаляются, даже если их TTL не истёк.

$taggedCache->startTagCache($cacheDir);
$taggedCache->registerTag('iblock_id_5');
// ... запрос к БД ...
$taggedCache->endTagCache();
$cache->endDataCache($data);

// При изменении элемента инфоблока 5:
$taggedCache->clearByTag('iblock_id_5');

Почему Redis предпочтительнее Memcached для Битрикс?​

Redis поддерживает нативное тегированное кэширование через структуры данных (множества). Memcached — нет, Битрикс эмулирует теги дополнительными ключами. Redis опционально сохраняет данные на диск (персистентность). Redis поддерживает кластеризацию и репликацию.

Что такое Композитный сайт?​

Технология разделения страницы на статичную и динамическую части. Статичный HTML-каркас отдаётся мгновенно из кэша. Динамические блоки (корзина, имя пользователя) подгружаются отдельным AJAX-запросом и вставляются в DOM через JavaScript. Время отображения страницы — десятки миллисекунд.

5. Компоненты и модули​

Что такое class.php и чем он отличается от component.php?​

component.php — процедурный стиль, логика выполняется при подключении файла. class.php — объектно-ориентированный: определяется класс-наследник CBitrixComponent с методом executeComponent(). Второй подход предпочтителен: явный жизненный цикл, наследование, unit-тестирование.

Зачем нужен result_modifier.php?​

Выполняется после компонента и до шаблона. Позволяет дополнить $arResult в конкретном шаблоне, не изменяя логику самого компонента. Удобно для «шаблонных» правок — преобразование дат, форматирование цен — без перегрузки компонента.

Как работает кэш компонентов?​

// В executeComponent():
if ($this->startResultCache(3600)) {     // Если кэш устарел
    $this->arResult = $this->loadData();
    $this->endResultCache();             // Сохранить кэш
}
$this->includeComponentTemplate();       // Вызывается всегда

startResultCache() возвращает true если кэша нет или он устарел. При false — данные берутся из кэша, loadData() не вызывается. abortResultCache() — прервать кэширование (например, если элемент не найден).

Из каких частей состоит установочный файл модуля?​

Класс в install/index.php наследует CModule и реализует методы DoInstall() и DoUninstall(). В DoInstall(): создание таблиц (InstallDB()), регистрация обработчиков событий, регистрация модуля через ModuleManager::registerModule(). В DoUninstall() — обратные действия.

6. Событийная модель​

Как зарегистрировать обработчик события?​

// Старое ядро
AddEventHandler('iblock', 'OnBeforeIBlockElementAdd', 'myHandler');

// D7
\Bitrix\Main\EventManager::getInstance()->addEventHandler(
    'iblock',
    'OnBeforeIBlockElementAdd',
    [\MyClass::class, 'myHandler']
);

Как отменить действие в обработчике?​

В обработчиках OnBefore* старого ядра — вернуть false и установить ошибку:

function myHandler(array &$arFields): bool
{
    global $APPLICATION;
    $APPLICATION->ThrowException('Нельзя');
    return false;
}

В D7-событиях — вернуть EventResult с типом ERROR:

return new \Bitrix\Main\EventResult(
    \Bitrix\Main\EventResult::ERROR,
    'Нельзя',
    'vendor.mymodule'
);

Чем addEventHandler отличается от registerEventHandler?​

addEventHandler добавляет обработчик только в рамках текущего запроса (подходит для init.php). registerEventHandler записывает обработчик в базу данных — он загружается автоматически при каждом запросе, без необходимости вызова в init.php. Используется в методе DoInstall() модуля.

7. REST-контроллеры и агенты​

Как создать собственный AJAX-endpoint в Битрикс?​

Наследовать класс от \Bitrix\Main\Engine\Controller, создать метод {name}Action(). Параметры метода типизируются и заполняются из запроса автоматически.

class MyController extends \Bitrix\Main\Engine\Controller
{
    public function getDataAction(int $id): array
    {
        return ['item' => SomeTable::getById($id)->fetch()];
    }
}

Вызов: POST /bitrix/services/main/ajax.php?action=vendor.mymodule:myController.getData

Зачем выносить агенты на Cron?​

На хитах агент выполняется в момент загрузки страницы — замедляет ответ для пользователя. Если трафика нет — агент не выполняется вовсе (письма не уходят, импорт не работает). Cron запускает агенты по расписанию, независимо от посетителей. Для продакшн-среды Cron обязателен.

8. Безопасность​

Как защититься от CSRF?​

В форму добавить <?= bitrix_sessid_post() ?>, при обработке POST проверять check_bitrix_sessid(). В D7-контроллерах — ActionFilter\Csrf в preflight-фильтрах.

Как защититься от SQL-инъекций?​

Использовать D7 ORM — все запросы параметризуются автоматически. Для legacy-кода с прямым $DB->Query() — приводить числа к типу (int), строки экранировать через $DB->ForSQL($value, $maxLength).

Как защититься от XSS?​

При выводе данных в HTML всегда использовать htmlspecialcharsbx(). Никогда не выводить пользовательский ввод напрямую. Данные из визуального редактора (доверенный источник) выводить как есть; контент от пользователей очищать.

Как передавать изменения структуры БД между средами?​

Через модуль миграций (например, sprint.migration): изменения описываются как PHP-классы с методами up()/down(), файлы коммитятся в git, при деплое выполняются автоматически. Для изменений таблиц собственного модуля — SQL-файлы в install/db/.

9. Дополнительные темы​

Что такое Highload-блок и когда его использовать?​

Highload-блок — абстракция над произвольной плоской таблицей в БД, работающая через D7 ORM. Все поля хранятся в одной таблице (плоская модель, в отличие от EAV у инфоблоков). Применяется для больших справочников (от 100 000+ записей), технических данных без SEO-требований, высоконагруженных операций чтения/записи. Не применяется для каталогов и новостей с иерархией и SEO.

Зачем выносить бизнес-логику из шаблонов в сервисный слой?​

Логика в template.php и result_modifier.php нетестируема, не переиспользуется. При дублировании логики в нескольких компонентах — изменение нужно вносить везде. Сервисные классы (/local/modules/vendor.mymodule/lib/service/) покрываются юнит-тестами, переиспользуются в разных компонентах и контроллерах, не зависят от Битрикс-специфики.

Как работает очередь почты в Битрикс?​

CEvent::Send() не отправляет письмо сразу — записывает его в таблицу b_event. Агент CEvent::CheckEvents() обходит очередь и отправляет письма. На продакшне этот агент должен выполняться через Cron. Если оставить на хитах, при отсутствии трафика письма зависнут в очереди.

Что такое мультисайтовость в Битрикс?​

Возможность обслуживать несколько сайтов из одной установки Битрикс, используя одну кодовую базу и одну или несколько БД. Сайты различаются по домену или директории. Настройки хранятся в b_lang. Каждый сайт может иметь свои шаблоны, компоненты и языковые файлы. Данные (инфоблоки, пользователи) могут быть общими или раздельными в зависимости от настроек.
