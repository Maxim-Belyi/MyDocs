Сети и Безопасность (Networks & Security)

Сетевая грамотность — обязательный навык бэкендера. На собеседованиях проверяют понимание базовых протоколов (Транспортный уровень OSI) и механизмов защиты веб-приложений.

1. Транспортный уровень (TCP/UDP)​

Какие есть протоколы транспортного уровня? Принципиальное отличие TCP от UDP?​

На транспортном уровне (4 уровень модели OSI) работают два основных протокола: TCP и UDP.

  • TCP (Transmission Control Protocol):
    • Обеспечивает гарантированную доставку.
    • Устанавливает соединение перед отправкой ("Тройное рукопожатие" / 3-way handshake).
    • Следит за порядком пакетов (собирает их в правильной последовательности на принимающей стороне).
    • Запрашивает повторную отправку, если пакет потерялся.
    • Использование: HTTP/HTTPS, базы данных, передача файлов, SSH.
  • UDP (User Datagram Protocol):
    • Отправляет данные "вслепую" (fire and forget). Никаких гарантий доставки, никакого рукопожатия.
    • Пакеты могут прийти в другом порядке или не прийти вообще.
    • Работает гораздо быстрее, чем TCP.
    • Использование: Стриминг видео, онлайн-игры, DNS-запросы, VoIP (звонки).

2. Прикладной уровень (HTTP и DNS)​

Что такое DNS и как он работает?​

DNS (Domain Name System) — это "телефонная книга" интернета. Она переводит человекочитаемые доменные имена (например, google.com) в IP-адреса машин (например, 142.250.190.46), с которыми браузеру нужно установить TCP соединение. Как работает: Браузер сначала смотрит локальный кеш и файл hosts. Если не находит — отправляет UDP-запрос к локальному DNS-серверу (выданному провайдером). Тот по цепочке опрашивает корневые сервера, сервера зоны (TLD, например .com), пока не получит точный IP-адрес нужного домена.

Из каких частей состоит HTTP запрос?​

  1. Стартовая строка (Start line): Содержит HTTP-метод (GET, POST, etc.), URI (путь) и версию протокола (HTTP/1.1).
  2. Заголовки (Headers): Метаданные запроса в формате Key: Value. Например: Host: google.com, Authorization: Bearer token, Content-Type: application/json.
  3. Пустая строка: Обязательный разделитель между заголовками и телом.
  4. Тело (Body): Полезная нагрузка (например, JSON с данными регистрации). Отсутствует у GET-запросов.

Зачем нужны тайм-ауты в HTTP запросах и как их подобрать?​

Тайм-ауты критически необходимы. Если вы делаете HTTP-запрос к стороннему API (или БД), а сервер там "завис" (он не закрывает соединение, но и не шлет данные), ваша горутина будет заблокирована бесконечно. Если к вам придет 1000 пользователей — 1000 ваших горутин зависнут, исчерпают лимит открытых сокетов (file descriptors) или память, и ваш сервис упадет. Подбор: Подбирается по метрикам. Смотрят 99-й перцентиль (p99) времени ответа стороннего сервиса. Если 99% запросов выполняются за 200мс, тайм-аут разумно поставить в 300-500мс.

3. Web Безопасность​

Принципиальное отличие HTTPS от HTTP? А что не шифруется в HTTP запросе?​

HTTPS = HTTP + TLS/SSL шифрование. При использовании HTTP весь трафик передается в открытом виде (plaintext). Любой промежуточный узел (роутер в кафе, провайдер) может прочитать пароли и заголовки. HTTPS шифрует всё содержимое симметричными ключами, которые безопасно согласовываются на этапе TLS-хендшейка с использованием асимметричной криптографии (сертификатов). Что НЕ шифруется в HTTPS? Не шифруется IP-адрес назначения, порт и, самое главное, доменное имя (отправляется в открытом виде в рамках расширения SNI — Server Name Indication на этапе рукопожатия). Провайдер всегда знает, на какой сайт вы идете, но не видит, какие именно страницы (URL пути) вы там читаете.

Что такое Man in the Middle (MitM)? Как предотвратить?​

Атака "Человек посередине" — ситуация, когда злоумышленник тайно перехватывает (и возможно изменяет) связь между двумя сторонами, которые считают, что общаются напрямую. Последствия: Кража паролей, сессий, подмена реквизитов при переводах денег. Как лечить: Использовать исключительно HTTPS. Браузер проверяет SSL-сертификат сайта через доверенные центры сертификации (CA). Если хакер подсунет свой сертификат, браузер выдаст огромную красную ошибку. (В мобильных приложениях используют SSL Pinning — жестко вшивают хэш сертификата прямо в код приложения).

Что такое CSRF? Как его лечить?​

CSRF (Cross-Site Request Forgery) — межсайтовая подделка запроса. Хакер заманивает вас на свой зловредный сайт evil.com. На этом сайте есть невидимая форма или картинка, которая делает POST-запрос на bank.com/transfer?amount=1000&to=hacker. Если вы в этот момент залогинены в bank.com, ваш браузер автоматически прикрепит ваши куки (Session ID) к этому запросу, и банк подумает, что вы сами перевели деньги. Как лечить:

  1. Использовать CSRF-токены (специальный секретный токен, который сервер передает в скрытом поле формы, а браузер должен вернуть обратно. В куках он не передается).
  2. Современный способ: атрибут SameSite=Lax или SameSite=Strict для всех Session Cookie.

CORS - что это такое?​

CORS (Cross-Origin Resource Sharing) — это механизм браузера (не сервера!), который блокирует AJAX-запросы (fetch/XHR) с вашего сайта (site.com) к чужому API (api.example.com), если чужой сервер явно не разрешит это. Браузер отправляет предварительный OPTIONS запрос (preflight). Если сервер отвечает заголовком Access-Control-Allow-Origin: https://site.com, то браузер делает реальный POST/GET запрос. Если заголовка нет, запрос падает с классической ошибкой CORS в консоли. Это защита браузера, чтобы зловредные скрипты не читали данные с чужих сайтов от лица пользователя.
