Система контроля версий (Git)

На собеседованиях часто проверяют не только знание базовых команд (commit/push), но и понимание того, как устроена работа с историей и конфликтами в Git.

1. Базовые операции и ветвление​

Как можно переключиться между ветками?​

  • Старый способ (может путать, так как используется и для восстановления файлов): git checkout <branch_name>
  • Новый, более семантически правильный способ (с версии Git 2.23): git switch <branch_name>
  • Создать ветку и сразу переключиться на нее: git checkout -b <branch_name> или git switch -c <branch_name>.

Как склонировать себе ровно одну ветку (чтобы не тянуть всю историю)?​

Если репозиторий огромный (миллионы коммитов во всех ветках), а вам нужна только одна ветка для быстрой работы (или CI/CD пайплайна), используйте: git clone -b <branch_name> --single-branch <url>

2. Слияние и работа с историей​

Что делает git pull под капотом?​

Команда git pull — это составная команда. На самом деле она последовательно делает две вещи:

  1. git fetch — скачивает все новые метаданные и коммиты с удаленного репозитория (origin) в локальный кэш, но не меняет ваши рабочие файлы.
  2. git merge origin/<branch> — автоматически сливает скачанные изменения в вашу текущую локальную ветку. (Примечание: если настроено pull.rebase = true, вторым шагом будет выполнен git rebase вместо merge).

Что делает git merge?​

Сливает изменения из одной ветки в другую. При этом создается новый специальный merge-коммит, который имеет двух предков (родителей) и объединяет историю обеих веток. Полезно для вливания фиче-веток в основную (main).

Что делает git cherry-pick?​

Позволяет выцепить один конкретный коммит (по его хэшу) из любой другой ветки и применить его (скопировать изменения) поверх вашей текущей ветки. Очень полезно, когда кто-то исправил критический баг в фиче-ветке, и вам нужно забрать только это исправление в релизную ветку, не затягивая (не мерджа) всю фиче-ветку целиком.

Как удалить файл из коммита?​

Если вы случайно добавили файл (например, пароли .env или бинарник) и сделали git commit, но еще не пушили (не делали git push), вы можете удалить его из коммита, оставив на диске:

  1. git rm --cached <file> (удаляет файл из отслеживания Git).
  2. git commit --amend --no-edit (перезаписывает последний коммит уже без этого файла).

Если вы уже запушили файл, его нужно удалять отдельным коммитом, или переписывать историю всего репозитория через git filter-branch (или BFG Repo-Cleaner), так как файл останется в истории старых коммитов.
