Группировка, агрегаты и порядок выполнения запроса

Группировка данных в SQL позволяет объединять строки с одинаковыми значениями в определенных столбцах в сводные группы для вычисления итоговых статистических показателей (агрегаций).

1. Агрегатные функции​

Агрегатные функции вычисляют одно итоговое значение на основе набора входных строк. По умолчанию все агрегатные функции, кроме COUNT(*), игнорируют значения NULL.

  • COUNT(*): Подсчитывает общее количество строк в группе, включая строки со значениями NULL.
  • COUNT(column): Подсчитывает количество строк, в которых column IS NOT NULL.
  • COUNT(DISTINCT column): Подсчитывает количество уникальных не-NULL значений в столбце.
  • SUM(column): Вычисляет арифметическую сумму всех значений в числовом столбце.
  • AVG(column): Вычисляет среднее арифметическое значение (SUM / COUNT).
  • MIN(column): Находит минимальное значение (применимо к числам, датам и строкам).
  • MAX(column): Находит максимальное значение.

2. Оператор GROUP BY​

Оператор GROUP BY группирует строки таблицы по уникальным значениям указанных столбцов.

SELECT department_id, COUNT(*) AS employees_count, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id;

Жесткое правило GROUP BY​

Если в запросе используется GROUP BY, то в блоке SELECT разрешено обращаться только к:

  1. Столбцам, явно перечисленным в предложении GROUP BY.
  2. Агрегатным функциям от любых столбцов (COUNT, SUM, MAX и т.д.).

Попытка выбрать обычный столбец, не входящий в GROUP BY и не обернутый в агрегатную функцию, приведет к синтаксической ошибке в стандартах SQL (SQL:1999+) и СУБД PostgreSQL/Oracle:

-- ОШИБКА: столбец "employees.name" должен присутствовать в предложении GROUP BY 
-- или использоваться в агрегатной функции
SELECT department_id, name, AVG(salary)
FROM employees
GROUP BY department_id;

3. Фильтрация групп: HAVING vs WHERE​

Для фильтрации данных в группирующих запросах используются два оператора: WHERE и HAVING. Они не взаимозаменяемы и применяются на разных этапах выполнения.

WHERE​

Фильтрует исходные отдельные строки до выполнения группировки и вычисления агрегатов. В WHERE нельзя использовать агрегатные функции.

HAVING​

Фильтрует уже сформированные группы после выполнения группировки и расчета агрегатов. В HAVING можно и нужно проверять результаты агрегатных функций.

-- Пример комбинирования WHERE и HAVING:
-- 1. WHERE: отсеиваем стажеров (role != 'intern') до группировки
-- 2. GROUP BY: группируем оставшихся по отделам
-- 3. HAVING: оставляем только те отделы, где средняя зарплата штатных сотрудников > 100000
SELECT department_id, AVG(salary) AS avg_salary, COUNT(*) AS staff_count
FROM employees
WHERE role != 'intern'
GROUP BY department_id
HAVING AVG(salary) > 100000 AND COUNT(*) >= 5;

4. Логический порядок выполнения SQL-запроса​

Порядок, в котором разработчик пишет ключевые слова в запросе (синтаксический порядок), существенно отличается от фактического внутреннего порядка выполнения логического плана запроса в движке СУБД.

Синтаксический порядок (как мы пишем)​

  1. SELECT
  2. FROM
  3. JOIN / ON
  4. WHERE
  5. GROUP BY
  6. HAVING
  7. ORDER BY
  8. LIMIT / OFFSET

Логический порядок выполнения (как СУБД обрабатывает запрос)​

  1. FROM и JOIN: Определение источников данных, загрузка таблиц и вычисление декартова произведения или деплоя соединений по условиям ON.
  2. WHERE: Построчная фильтрация объединенного набора. Отсечение строк, не удовлетворяющих условию.
  3. GROUP BY: Разбиение оставшихся строк на логические группы или корзины.
  4. HAVING: Вычисление агрегатов для каждой группы и фильтрация самих групп.
  5. SELECT: Вычисление финальных выражений, проекция запрошенных столбцов и присвоение псевдонимов (AS alias).
  6. DISTINCT: Удаление строк-дубликатов из результирующего набора SELECT.
  7. ORDER BY: Сортировка финальной выборки по возрастанию (ASC) или убыванию (DESC). На этом этапе уже доступны псевдонимы, определенные на шаге SELECT.
  8. LIMIT и OFFSET: Усечение результирующего набора и пропуск указанного количества строк для пагинации.

Следствие для разработчика​

Понимание этого порядка объясняет, почему нельзя использовать псевдоним (alias), объявленный в SELECT, внутри блока WHERE или GROUP BY: эти блоки выполняются до того, как СУБД дойдет до вычисления блока SELECT.
