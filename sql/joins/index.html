JOIN-соединения и объединения наборов строк

В реляционных базах данных данные обычно распределены по нормализованным таблицам. Для выборки взаимосвязанных данных из двух и более таблиц в одном SQL-запросе используются операции соединения (JOIN). Для объединения результатов нескольких независимых запросов по вертикали применяются операторы UNION и UNION ALL.

1. Подготовка тестовых данных​

Для демонстрации работы видов JOIN используем две таблицы: departments (отделы) и employees (сотрудники).

CREATE TABLE departments (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    department_id INT REFERENCES departments(id)
);

INSERT INTO departments (id, name) VALUES
(10, 'IT'),
(20, 'HR'),
(30, 'Marketing'); -- Отдел без сотрудников

INSERT INTO employees (id, name, department_id) VALUES
(1, 'Алиса', 10),
(2, 'Боб', 10),
(3, 'Чарли', 20),
(4, 'Дэвид', NULL); -- Сотрудник без назначенного отдела

2. INNER JOIN (Внутреннее соединение)​

INNER JOIN (или просто JOIN) возвращает только те строки, для которых найдено совпадение в обеих соединяемых таблицах по условию ON. Строки, не имеющие пары ни в левой, ни в правой таблице, отсеиваются.

SELECT e.name AS employee_name, d.name AS department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;

Результат:

employee_namedepartment_name
АлисаIT
БобIT
ЧарлиHR

(Дэвид без отдела и Marketing без сотрудников не попали в выборку).

3. LEFT JOIN и RIGHT JOIN (Внешние соединения)​

LEFT JOIN (LEFT OUTER JOIN)​

Возвращает все строки из левой таблицы (employees), а также совпадающие строки из правой таблицы (departments). Если для строки из левой таблицы совпадений в правой нет, в столбцах правой таблицы возвращаются значения NULL.

SELECT e.name AS employee_name, d.name AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id;

Результат:

employee_namedepartment_name
АлисаIT
БобIT
ЧарлиHR
ДэвидNULL

RIGHT JOIN (RIGHT OUTER JOIN)​

Работает аналогично LEFT JOIN, но возвращает все строки из правой таблицы (departments) и совпадающие из левой (employees).

SELECT e.name AS employee_name, d.name AS department_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.id;

Результат:

employee_namedepartment_name
АлисаIT
БобIT
ЧарлиHR
NULLMarketing

4. FULL OUTER JOIN (Полное внешнее соединение)​

FULL OUTER JOIN объединяет результаты LEFT JOIN и RIGHT JOIN. Возвращает все строки из обеих таблиц. Если совпадение между строками найдено, они объединяются; если нет — недостающие поля заполняются NULL.

SELECT e.name AS employee_name, d.name AS department_name
FROM employees e
FULL OUTER JOIN departments d ON e.department_id = d.id;

Результат:

employee_namedepartment_name
АлисаIT
БобIT
ЧарлиHR
ДэвидNULL
NULLMarketing

5. CROSS JOIN (Декартово произведение)​

CROSS JOIN соединяет каждую строку первой таблицы с каждой строкой второй таблицы без условия ON. Если в первой таблице M строк, а во второй N строк, результирующий набор будет содержать M * N строк.

SELECT e.name, d.name AS potential_department
FROM employees e
CROSS JOIN departments d;

(Для 4 сотрудников и 3 отделов результат вернет 12 строк комбинаций).

6. Сравнение UNION и UNION ALL​

Операторы UNION и UNION ALL используются для объединения результатов двух или более запросов SELECT в один итоговый набор строк.

Требования к запросам​

  • Запросы должны возвращать одинаковое количество столбцов.
  • Совмещаемые столбцы должны иметь совместимые типы данных.
  • Порядок столбцов в каждом запросе должен совпадать.

Разница в работе и производительности​

UNION​

Объединяет результаты запросов и полностью удаляет все строки-дубликаты из итогового набора. Для выполнения дедупликации СУБД вынуждена выполнять сортировку или построение промежуточной хеш-таблицы по всем возвращаемым колонкам, что создает высокую нагрузку на процессор и память при больших объемах данных.

SELECT name FROM employees
UNION
SELECT name FROM departments;

UNION ALL​

Объединяет результаты запросов в исходном виде, сохраняя все дубликаты. СУБД просто последовательно дописывает строки второго запроса в конец строк первого без каких-либо затрат на сравнение и сортировку.

SELECT name FROM employees
UNION ALL
SELECT name FROM departments;

Рекомендация по выбору​

Всегда используйте UNION ALL по умолчанию. Применяйте UNION только в тех случаях, когда бизнес-логика строго требует исключения дубликатов из итогового набора, и нет возможности гарантировать уникальность данных на уровне исходных запросов.
