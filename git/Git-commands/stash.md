# Stash

Механизм `stash` во временное хранилище (стек отложенных изменений) позволяет сохранить текущие модификации рабочей директории и индекса (staging area) без создания коммита. Это применяется для переключения между ветками при наличии незавершенной работы.

---

## 1. Базовый синтаксис и сохранение изменений

Команда сохраняет отслеживаемые (tracked) модифицированные файлы и очищает рабочую директорию до состояния последнего коммита (`HEAD`).

```bash
# Сохранение изменений в стек
git stash push -m "Описание сохраненного состояния"

# Сокращенная команда (аналогична push без сообщения)
git stash
```

### Сохранение неиндексированных файлов
По умолчанию `git stash push` игнорирует новые (untracked) и игнорируемые (`.gitignore`) файлы. Для их включения используются флаги:

* `-u` (`--include-untracked`): Сохранить отслеживаемые изменения и новые файлы.
* `-a` (`--all`): Сохранить все изменения, включая игнорируемые файлы.

```bash
git stash push -u -m "Сохранение с новыми файлами"
```

---

## 2. Просмотр списка отложенных изменений

Каждое сохранение помещается в стек. Вывод списка сохраненных состояний:

```bash
git stash list
```

Пример вывода:
```text
stash@{0}: On main: Описание сохраненного состояния
stash@{1}: WIP on feature-auth: 4a2b1c3 Add login form
```

Где `stash@{0}` — последний добавленный элемент (вершина стека).

---

## 3. Применение и удаление изменений

Существует два основных способа вернуть сохраненные изменения в рабочую директорию:

### `git stash pop`
Применяет изменения из указанного элемента стека и автоматически удаляет этот элемент из списка `stash list` при отсутствии конфликтов. Если индекс не указан, применяется `stash@{0}`.

```bash
# Применение последнего сохранения с удалением из стека
git stash pop

# Применение конкретного сохранения
git stash pop stash@{1}
```

### `git stash apply`
Применяет изменения, но оставляет элемент в стеке отложенных изменений. Применяется, когда одно и то же состояние необходимо перенести на несколько разных веток.

```bash
git stash apply stash@{0}
```

---

## 4. Удаление и очистка стека

Для удаления записей без применения к рабочей директории используются команды:

```bash
# Удаление конкретного элемента из стека
git stash drop stash@{0}

# Полная очистка всего стека отложенных изменений
git stash clear
```

---

## 5. Создание ветки из stash

Если при выполнении `git stash pop` возникают сложные конфликты с текущим состоянием рабочей директории, можно создать новую ветку, начиная с коммита, на котором был создан `stash`:

```bash
git stash branch new-branch-name stash@{0}
```

Команда создает ветку `new-branch-name`, переключается на нее, применяет изменения и при успехе удаляет `stash@{0}` из стека.
