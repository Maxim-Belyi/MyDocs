# Точечный перенос коммитов (Cherry-pick)

Команда `git cherry-pick` позволяет выбрать один или несколько существующих коммитов из любой ветки и применить их изменения к текущей рабочей ветке в виде новых коммитов с новыми хешами.

---

## 1. Принцип работы и базовый синтаксис

При выполнении `cherry-pick` Git вычисляет разницу (diff), которую вносит выбранный коммит по сравнению со своим родителем, и применяет этот diff к вершине текущей ветки (`HEAD`).

```bash
# Перенос одного коммита по его хешу
git cherry-pick a1b2c3d

# Перенос нескольких отдельных коммитов
git cherry-pick a1b2c3d e4f5g6h

# Перенос диапазона коммитов (от коммита A до коммита B включительно)
# Примечание: коммит A должен быть предком коммита B
git cherry-pick a1b2c3d..e4f5g6h
```

---

## 2. Полезные флаги и аргументы

* `-x`: Добавляет в тело сообщения нового коммита строку вида `(cherry picked from commit ...)` с указанием исходного хеша. Стандартная практика при переносе исправлений (backport) в стабильные ветки для сохранения истории происхождения изменений.
* `-n` (`--no-commit`): Применяет изменения коммита к рабочей директории и индексу текущей ветки, но не создает новый коммит автоматически. Позволяет объединить изменения нескольких `cherry-pick` в один итоговый коммит или дополнительно отредактировать файлы перед сохранением.
* `-e` (`--edit`): Открывает текстовый редактор перед созданием коммита для изменения или дополнения сообщения.

```bash
# Перенос с фиксацией исходного хеша и редактированием сообщения
git cherry-pick -x -e a1b2c3d
```

---

## 3. Разрешение конфликтов

Если переносимый коммит модифицирует участки кода, которые отличаются в текущей ветке от родительского состояния исходного коммита, возникает конфликт слияния.

Процедура разрешения:

1. Открыть конфликтующие файлы в редакторе и разрешить коллизии.
2. Проиндексировать исправленные файлы:
   ```bash
   git add <путь-к-файлу>
   ```
3. Продолжить операцию переноса:
   ```bash
   git cherry-pick --continue
   ```

### Отмена операции
Если в процессе разрешения конфликта требуется прервать операцию и вернуть рабочую директорию в исходное состояние (до выполнения команды):

```bash
git cherry-pick --abort
```

---

## 4. Практические сценарии применения

* **Исправление критических ошибок (Hotfix / Backport):** Перенос коммита с багфиксом из ветки `main` в поддерживаемую релизную ветку (например, `release/v1.2`).
* **Ошибочный коммит в чужую ветку:** Если разработчик по ошибке сделал коммит в ветку `main` вместо своей `feature`-ветки, коммит переносится через `cherry-pick` в целевую ветку, а в `main` отменяется через `git reset`.
* **Извлечение отдельных изменений:** Перенос только необходимых наработок из долго живущей или экспериментальной ветки без выполнения полного слияния (`merge`).
