Индексы в базах данных (Laravel)

Нам нужны индексы. Индекс — это отдельная структура данных (обычно B-Tree), которая хранит отсортированные значения полей и ссылки на реальные строки в таблице. Вместо перебора миллионов строк база мгновенно находит нужные за миллисекунды.

В Laravel Schema Builder есть несколько методов для создания различных типов индексов. Правильный выбор типа индекса критически важен для производительности приложения.

1. Типы индексов в Laravel​

В Laravel доступны 5 основных типов индексов.

МетодОписание
$table->primary('id');Первичный ключ. Обычно создается автоматически через $table->id(), но может понадобиться для нестандартных таблиц.
$table->unique('email');Уникальный индекс. База данных не позволит вставить две записи с одинаковым значением в этой колонке.
$table->index('status');Обычный индекс. Ускоряет поиск (WHERE) и сортировку (ORDER BY) по данной колонке.
$table->fullText('body');Полнотекстовый индекс. Используется для быстрого поиска слов внутри больших объемов текста (работает в MySQL/PostgreSQL).
$table->spatialIndex('geo');Пространственный индекс. Применяется для гео-данных (координат, полигонов).

primary() (Первичный ключ)​

Первичный ключ уникально идентифицирует каждую строку в таблице. Он автоматически создает уникальный индекс. В таблице может быть только один первичный ключ.

$table->id(); // Под капотом создает первичный ключ `id`
// или явно:
$table->primary('id');
// Составной первичный ключ:
$table->primary(['user_id', 'post_id']);

Когда применять: Обязателен для каждой таблицы. Обычно это автоинкрементное поле id, реже — составной ключ в pivot-таблицах (таблицах связей).

unique() (Уникальный индекс)​

Гарантирует, что все значения в столбце (или комбинации столбцов) уникальны. Поиск по такому индексу очень быстрый, так как БД знает, что нужно остановиться после нахождения первого совпадения.

$table->string('email')->unique();
// или отдельно:
$table->unique('email');
// Составной уникальный индекс:
$table->unique(['user_id', 'role_id']);

Когда применять: Для полей, значения которых не должны повторяться: email, username, slug, артикул товара.

index() (Обычный индекс)​

Классический индекс (B-Tree), не накладывающий ограничений на уникальность. Служит исключительно для ускорения выборки данных (запросы WHERE, ORDER BY, GROUP BY).

$table->string('status')->index();
// или отдельно:
$table->index('status');
// Составной индекс:
$table->index(['account_id', 'created_at']);

Когда применять:

  • Для полей, по которым часто происходит поиск (фильтрация).
  • Для полей, которые участвуют в сортировке (ORDER BY).
  • Для полей внешних ключей.

fullText() (Полнотекстовый индекс)​

Специализированный индекс для поиска по тексту. Позволяет искать отдельные слова внутри больших текстов (работает с оператором MATCH ... AGAINST в MySQL и полнотекстовым поиском в PostgreSQL).

$table->text('body')->fullText();
// или отдельно:
$table->fullText('body');

Когда применять: Для быстрого текстового поиска по статьям, описаниям товаров, комментариям. Это альтернатива (или начальный этап) внедрения тяжелых поисковых движков вроде Elasticsearch.

spatialIndex() (Пространственный индекс)​

Используется для работы с географическими данными (точки, полигоны, геометрия). Ускоряет запросы типа "найти объекты в радиусе 5 км".

$table->geometry('positions')->spatialIndex();

Когда применять: Приложения с картами, геолокацией, поиском ближайших точек.

2. Именование индексов (Решение проблемы длинных имен)​

По умолчанию Laravel генерирует имена индексов на основе имени таблицы, имен столбцов и типа индекса (например, users_email_unique).

Иногда, если таблица и колонки имеют длинные названия, а вы делаете составной индекс, СУБД (особенно MySQL) может выдать ошибку: Identifier name is too long (лимит обычно составляет 64 символа).

В этом случае вы можете передать вторым аргументом свое короткое кастомное имя для индекса:

$table->unique('column', 'my_custom_index_name');
$table->index(['account_id', 'created_at'], 'idx_account_created');

3. Составные индексы и порядок колонок​

Вы можете создавать индексы, включающие несколько колонок:

$table->index(['team_id', 'status']);

[!CAUTION] Важность порядка (Правило крайнего левого префикса): Составной индекс [A, B] ускоряет запросы, где поиск идет по A или по A и B. Запрос, фильтрующий только по B, этот индекс использовать не будет. Всегда ставьте колонку, которая чаще всего используется в WHERE (или имеет самую высокую селективность — больше уникальных значений), первой!

4. Удаление индексов​

Для удаления индекса вы должны указать его имя. Если вы не задавали имя вручную, можно передать массив колонок, и Laravel сам вычислит стандартное имя:

// По явному имени:
$table->dropIndex('geo_state_index');
$table->dropUnique('users_email_unique');

// С вычислением имени Laravel (передаем массив колонок):
$table->dropIndex(['state']); // удалит `table_state_index`
$table->dropUnique(['email']); // удалит `table_email_unique`

5. Главные правила индексирования (Шпаргалка)​

  1. Не индексируйте всё подряд. Каждый индекс замедляет операции INSERT, UPDATE и DELETE, так как БД вынуждена перестраивать индексное дерево при каждом изменении.
  2. Индексы для внешних ключей. Рекомендуется индексировать колонки, которые используются в JOIN или на которые ссылаются другие таблицы.
  3. Селективность. Индексировать колонку с двумя значениями (например, boolean флаг is_active) часто бессмысленно — оптимизатор БД скорее всего проигнорирует индекс и сделает full table scan (полный скан таблицы). Однако составной индекс ['is_active', 'created_at'] уже может иметь смысл.
  4. Анализируйте запросы. Используйте EXPLAIN перед вашими запросами, чтобы увидеть, реально ли БД использует ваш индекс, или он простаивает и только замедляет запись.
