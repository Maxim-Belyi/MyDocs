# Типы полей в Laravel Schema Builder

**Schema Builder** — это встроенный в Laravel инструмент для создания и изменения таблиц БД через PHP-код, без написания SQL-запросов вручную. Он работает поверх любой СУБД, которую поддерживает Laravel (MySQL, PostgreSQL, SQLite, SQL Server), и предоставляет единый API вне зависимости от конкретной базы данных.

Таблицы создаются через `Schema::create()`, где второй параметр — замыкание, получающее объект `Blueprint`. Именно через этот объект объявляются все поля:

```php
Schema::create('users', function (Blueprint $table) {
    $table->increments('id');
    $table->string('email')->unique();
    $table->timestamps();
});
```

---

## 1. Целочисленные типы

Выбор правильного «размера» числа важен для экономии места и корректной работы внешних ключей.

| Метод | SQL-тип | Диапазон | Когда использовать |
|---|---|---|---|
| `$table->tinyInteger('flag')` | `TINYINT` | -128 … 127 | Статусы, флаги, маленькие счётчики |
| `$table->smallInteger('votes')` | `SMALLINT` | -32 768 … 32 767 | Небольшие числа без риска переполнения |
| `$table->mediumInteger('numbers')` | `MEDIUMINT` | ~-8 млн … 8 млн | Промежуточный вариант (реже используется) |
| `$table->integer('votes')` | `INTEGER` | ~-2 млрд … 2 млрд | Стандартный тип для большинства числовых полей |
| `$table->bigInteger('views')` | `BIGINT` | ~-9 квинтиллионов … 9 квинтиллионов | Счётчики с потенциально огромными значениями |

### Автоинкремент (первичный ключ)

Для первичного ключа с автоинкрементом есть специальные методы — они сами проставляют `UNSIGNED` и `PRIMARY KEY`:

```php
$table->increments('id');       // UNSIGNED INT, autoincrement — стандартный вариант
$table->bigIncrements('id');    // UNSIGNED BIGINT, autoincrement — для высоконагруженных проектов
```

> [!TIP]
> **Правило внешних ключей:** если родительская таблица использует `bigIncrements('id')`, то дочерняя таблица должна ссылаться на неё через `bigInteger('parent_id')->unsigned()`, а не просто `integer()`. Несовпадение типов приведёт к ошибке при создании внешнего ключа.

## 2. Дробные числа

Три разных типа для работы с числами с плавающей точкой, и у каждого свой сценарий.

| Метод | SQL-тип | Точность | Когда использовать |
|---|---|---|---|
| `$table->float('amount')` | `FLOAT` | ~7 значащих цифр | Физические величины, координаты — там где небольшая погрешность допустима |
| `$table->double('column', 15, 8)` | `DOUBLE` | ~15 значащих цифр | Научные расчёты, повышенная точность |
| `$table->decimal('amount', 5, 2)` | `DECIMAL(5,2)` | Точное | **Деньги, финансы, налоги** — любые расчёты, где потеря точности недопустима |

> [!CAUTION]
> `FLOAT` и `DOUBLE` хранят числа в бинарном формате и **не подходят для финансов** — там неизбежны погрешности округления (например, `0.1 + 0.2 ≠ 0.3`). Для денег всегда используйте `DECIMAL`.

Синтаксис `decimal('amount', 5, 2)` означает: всего 5 цифр, из которых 2 — после запятой. То есть максимальное значение — `999.99`.

## 3. Строки и текст

Выбор строкового типа влияет на производительность: по `VARCHAR`-полям можно строить индексы, по `TEXT` — нет.

| Метод | SQL-тип | Лимит | Когда использовать |
|---|---|---|---|
| `$table->char('code', 4)` | `CHAR(4)` | Фиксированная длина | Коды фиксированной длины: коды стран (`RU`), аббревиатуры |
| `$table->string('email')` | `VARCHAR(255)` | 255 символов | Имена, email, заголовки — стандартный тип для большинства строк |
| `$table->string('name', 100)` | `VARCHAR(100)` | Указанная длина | Строки с явно ограниченной длиной |
| `$table->text('description')` | `TEXT` | ~65 КБ | Описания, комментарии, небольшие тексты |
| `$table->mediumText('body')` | `MEDIUMTEXT` | ~16 МБ | Статьи, HTML-контент, markdown |
| `$table->longText('content')` | `LONGTEXT` | ~4 ГБ | Огромные документы, логи, дампы |

## 4. Булевый тип

```php
$table->boolean('confirmed');
```

Хранит `true`/`false`. На уровне БД реализуется по-разному: в MySQL это `TINYINT(1)`, в PostgreSQL — нативный `BOOLEAN`. Laravel прозрачно обрабатывает преобразование при чтении через Eloquent.

---

## 5. Двоичные данные

```php
$table->binary('data');
```

Создаёт поле типа `BLOB` — для хранения произвольных бинарных данных (файлы, изображения, зашифрованные данные). На практике хранить файлы прямо в БД — плохая практика: это замедляет бэкапы и усложняет работу с файлами. Чаще в базе хранят только **путь** к файлу в файловой системе или облаке.

## 6. Дата и время

Самая «многословная» группа — у каждого типа своя семантика.

| Метод | SQL-тип | Хранит | Когда использовать |
|---|---|---|---|
| `$table->date('birthday')` | `DATE` | Только дату (`2026-08-12`) | Дни рождения, даты событий без привязки к времени |
| `$table->time('sunrise')` | `TIME` | Только время (`08:30:00`) | Расписания, таймеры без конкретной даты |
| `$table->dateTime('scheduled_at')` | `DATETIME` | Дату + время (`2026-08-12 08:30:00`) | Запланированные события, история действий |
| `$table->timestamp('added_on')` | `TIMESTAMP` | Дату + время в UTC | Временны́е метки с автоматическим хранением в UTC |
| `$table->timestamps()` | 2 поля `DATETIME` | `created_at` и `updated_at` | **Используется почти везде** — Eloquent управляет этими полями автоматически |
| `$table->nullableTimestamps()` | 2 поля | То же, но допускает `NULL` | Когда дата создания или обновления может быть неизвестна |

> [!NOTE]
> При использовании `timestamps()` Eloquent **автоматически** проставляет `created_at` при создании записи и обновляет `updated_at` при каждом сохранении. Отказываться от этих полей без весомой причины не стоит — они почти ничего не стоят, но сильно упрощают отладку и аудит.

## 7. Перечисление (ENUM)

```php
$table->enum('status', ['draft', 'published', 'archived']);
```

Поле принимает только одно из заранее перечисленных значений. Удобно для статусов и категорий с фиксированным набором вариантов.

> [!WARNING]
> `ENUM` плохо поддаётся изменению: добавление нового варианта в MySQL требует перестройки таблицы (`ALTER TABLE`). Переименование ENUM-поля через `renameColumn()` также не поддерживается. Альтернатива — хранить строковые константы в `string`-поле и контролировать допустимые значения на уровне приложения.

## 8. Специальные типы Laravel

Это не просто SQL-типы, а «умные» шорткаты, которые создают несколько полей или добавляют определённую семантику.

### `softDeletes()` — мягкое удаление

```php
$table->softDeletes();
```

Добавляет поле `deleted_at TIMESTAMP NULL`. Когда Eloquent-модель использует трейт `SoftDeletes`, вместо физического удаления строки из БД он записывает в это поле текущую дату. Записи с непустым `deleted_at` автоматически исключаются из обычных запросов — это позволяет восстанавливать «удалённые» данные и сохранять историю.

### `morphs()` — полиморфные связи

```php
$table->morphs('taggable');
// Создаёт два поля:
// taggable_id   INTEGER
// taggable_type VARCHAR
```

Используется для **полиморфных отношений**, когда одна таблица может быть связана с несколькими разными моделями. Например, таблица `comments` может ссылаться и на `Post`, и на `Video` — тип модели хранится в `_type`, а её ID — в `_id`.

### `rememberToken()` — токен «Запомнить меня»

```php
$table->rememberToken();
// Создаёт поле: remember_token VARCHAR(100) NULL
```

Добавляет стандартное поле для функции «Запомнить меня» в системе аутентификации Laravel. Это поле ожидает встроенная система Auth — оно должно быть в таблице `users`.

## 9. Модификаторы полей

Большинство методов возвращают объект поля, на котором можно вызвать дополнительные модификаторы.

| Модификатор | Что делает |
|---|---|
| `->nullable()` | Разрешает значение `NULL`. По умолчанию все поля `NOT NULL` |
| `->default($value)` | Устанавливает значение по умолчанию |
| `->unsigned()` | Делает числовое поле беззнаковым (только положительные числа, вдвое больший диапазон) |
| `->after('column')` | Вставляет поле после указанного (только MySQL) |

Пример использования:

```php
$table->integer('sort_order')->unsigned()->default(0);
$table->string('bio')->nullable();
$table->string('avatar')->nullable()->after('email');
```

## Итоговая шпаргалка по выбору типа

| Задача | Метод |
|---|---|
| Первичный ключ | `increments()` / `bigIncrements()` |
| Целое число | `integer()` / `bigInteger()` |
| Деньги, точные дроби | `decimal('amount', 8, 2)` |
| Стандартная строка (email, имя) | `string()` |
| Длинный текст (статья, описание) | `text()` / `mediumText()` / `longText()` |
| Дата и время | `dateTime()` / `timestamps()` |
| Булев флаг | `boolean()` |
| Статус из фиксированного набора | `enum()` |
| Мягкое удаление | `softDeletes()` |
| Полиморфная связь | `morphs()` |
