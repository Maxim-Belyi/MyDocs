Память и производительность

PHP использует подсчёт ссылок (reference counting) для управления памятью и имеет встроенный сборщик мусора для обработки циклических ссылок. Генераторы позволяют обрабатывать большие объёмы данных без загрузки всего набора в память.

1. Ссылки в PHP (&)​

По умолчанию PHP передаёт значения по значению (создаётся копия). Оператор & создаёт ссылку — два имени, указывающих на один и тот же контейнер значения (zval).

// Присваивание по значению
$a = 10;
$b = $a; // Копия
$b = 20;
echo $a; // 10 — оригинал не изменился

// Присваивание по ссылке
$a = 10;
$b = &$a; // $b — ссылка на тот же zval, что и $a
$b = 20;
echo $a; // 20 — оригинал изменён!

// Разрыв ссылки
unset($b); // Только разрывает связь, $a остаётся
echo $a;   // 20

Передача в функцию по ссылке​

function addTax(float &$price, float $rate): void
{
    $price *= (1 + $rate);
}

$price = 100.0;
addTax($price, 0.2);
echo $price; // 120.0 — изменён оригинал

Ловушка в foreach​

Это классическая ошибка. При итерации по ссылке &$item переменная остаётся ссылкой на последний элемент после цикла.

$arr = [1, 2, 3, 4, 5];

foreach ($arr as &$item) {
    $item *= 2;
}
// ОПАСНО: $item всё ещё ссылается на $arr[4]

foreach ($arr as $item) { // На первой итерации $item = $arr[0] = 2, но $arr[4] &= $item = 2
    echo $item . ' ';    // Результат неожиданный!
}
// Правильно: всегда делать unset($item) после foreach с ссылками
unset($item);

2. Управление памятью: Reference Counting​

PHP управляет памятью через счётчик ссылок (refcount). Каждая переменная ссылается на контейнер значения (zval). Когда счётчик падает до 0, память освобождается немедленно.

$a = "hello"; // zval: value="hello", refcount=1
$b = $a;      // PHP оптимизирует: refcount=2, данные не копируются (Copy-on-Write)
$b .= " world"; // Теперь b изменяется — создаётся отдельная копия: refcount(a)=1, refcount(b)=1
unset($a);    // refcount(a)=0 → память освобождена немедленно

Copy-on-Write (CoW)​

PHP не копирует данные при присваивании переменной другой переменной. Копирование происходит только в момент, когда одна из переменных модифицируется. Это экономит память при передаче больших массивов в функции.

3. Циклические ссылки и Garbage Collector​

Стандартный reference counting не справляется с циклическими ссылками. Если объект A ссылается на B, а B ссылается на A, их счётчики никогда не упадут до 0, даже если снаружи нет ссылок на них.

class Node
{
    public ?Node $next = null;
}

$a = new Node(); // refcount($a) = 1
$b = new Node(); // refcount($b) = 1

$a->next = $b;   // refcount($b) = 2
$b->next = $a;   // refcount($a) = 2

unset($a);       // refcount($a) = 1 (ссылка из $b->next)
unset($b);       // refcount($b) = 1 (ссылка из $a->next)
// Оба объекта недостижимы, но refcount > 0 → утечка памяти!

Для таких случаев в PHP есть Cycle Garbage Collector (Zend GC), который периодически обходит граф объектов и находит недостижимые циклические структуры.

// Принудительный запуск GC (обычно не нужен — срабатывает автоматически)
gc_collect_cycles();

// Проверка состояния
echo gc_enabled() ? 'GC включён' : 'GC выключён';

GC запускается автоматически, когда буфер потенциально циклических переменных достигает 10 000. Для долгоживущих скриптов (CLI-демоны, очереди) следует явно вызывать gc_collect_cycles() в конце каждой итерации и использовать unset() для больших объектов.

4. Генераторы (yield)​

Генератор — это функция, которая может приостанавливать своё выполнение и возобновлять его при следующем запросе значения. При каждом вызове yield функция возвращает значение и замораживает состояние (стек, локальные переменные).

Зачем нужны генераторы​

Обычная функция, возвращающая большую коллекцию, загружает её целиком в память:

// Без генератора — весь файл в памяти
function readAllLines(string $file): array
{
    return file($file); // Например, 10 млн строк → сотни МБ
}

// С генератором — в памяти только одна строка
function readLines(string $file): \Generator
{
    $handle = fopen($file, 'r');
    while (($line = fgets($handle)) !== false) {
        yield trim($line); // Возвращает строку и замирает
    }
    fclose($handle);
}

foreach (readLines('huge_log.txt') as $line) {
    processLine($line); // Обрабатываем построчно, памяти нужно минимум
}

Генераторы с ключами​

function indexedValues(): \Generator
{
    yield 'first'  => 1;
    yield 'second' => 2;
    yield 'third'  => 3;
}

foreach (indexedValues() as $key => $value) {
    echo "$key: $value\n";
}

yield from — делегирование генераторов​

function inner(): \Generator
{
    yield 1;
    yield 2;
}

function outer(): \Generator
{
    yield 0;
    yield from inner(); // Делегирует inner-генератору
    yield 3;
}

foreach (outer() as $v) {
    echo $v . ' '; // 0 1 2 3
}

Отправка данных в генератор (send)​

Генератор может не только производить данные, но и принимать их через send():

function accumulator(): \Generator
{
    $total = 0;
    while (true) {
        $value = yield $total; // Возвращает текущий total, принимает следующее значение
        if ($value === null) break;
        $total += $value;
    }
}

$gen = accumulator();
$gen->current(); // Запускаем генератор (до первого yield)
echo $gen->send(10); // 10
echo $gen->send(20); // 30
echo $gen->send(5);  // 35

5. Оптимизация потребления памяти — практические рекомендации​

  1. Используйте генераторы при обработке больших файлов, таблиц БД или любых последовательностей, которые не нужны целиком одновременно.
  2. unset() крупных временных переменных внутри длинных циклов в CLI-скриптах.
  3. SplFixedArray вместо обычного массива, если размер известен заранее и элементы только числовые. Потребляет меньше памяти, так как не хранит хеш-таблицу ключей.
  4. Используйте array_chunk() для обработки данных батчами вместо загрузки всего результата в массив.
  5. В Laravel используйте cursor() для Eloquent-запросов вместо get() при обработке больших таблиц: cursor() возвращает генератор, загружая по одной записи.
// Eloquent cursor() — генератор, одна запись в памяти
foreach (User::where('active', true)->cursor() as $user) {
    $user->sendNotification();
}

// Vs get() — все записи сразу в памяти
$users = User::where('active', true)->get(); // Может быть 100 000 объектов
