Память и производительность

Когда PHP выполняет ваш скрипт, он хранит все переменные, объекты и данные в оперативной памяти сервера. Если скрипт неаккуратно работает с памятью — она заканчивается, сервер «падает» или начинает тормозить. Это особенно критично для долгоживущих скриптов (обработчики очередей, CLI-команды, импорт больших файлов).

PHP управляет памятью автоматически через подсчёт ссылок и сборщик мусора. Понимание этих механизмов помогает писать эффективный код и объяснять на собеседовании, почему генераторы лучше массивов при обработке больших данных.

1. Ссылки в PHP (&)​

По умолчанию PHP передаёт значения по значению — это значит, что при присвоении одной переменной другой создаётся копия данных. Изменение копии не затрагивает оригинал.

Оператор & создаёт ссылку — два имени, указывающих на одни и те же данные в памяти. Изменение одного немедленно меняет второе.

// Присваивание по значению — создаётся копия
$a = 10;
$b = $a; // Копия
$b = 20;
echo $a; // 10 — оригинал не изменился

// Присваивание по ссылке — два имени для одного места в памяти
$a = 10;
$b = &$a; // $b и $a смотрят на одни и те же данные
$b = 20;
echo $a; // 20 — оригинал изменён!

// Разрыв ссылки
unset($b); // Только разрывает связь, $a остаётся
echo $a;   // 20

Аналогия: Значение по умолчанию — это фотокопия документа. Ссылка (&) — это когда двое людей держат один и тот же оригинальный документ. Если один что-то зачеркнул — второй видит то же самое.

Передача в функцию по ссылке​

Полезно, когда функция должна изменить переданное значение, а не вернуть новое:

function addTax(float &$price, float $rate): void
{
    $price *= (1 + $rate);
}

$price = 100.0;
addTax($price, 0.2);
echo $price; // 120.0 — изменён оригинал

⚠️ Классическая ловушка в foreach​

Это самая частая ошибка с ссылками в PHP — её проверяют на собеседованиях. После цикла с &$item переменная остаётся ссылкой на последний элемент массива!

$arr = [1, 2, 3, 4, 5];

foreach ($arr as &$item) {
    $item *= 2;
}
// После цикла: $item ссылается на $arr[4] (последний элемент)!

foreach ($arr as $item) {
    // На первой итерации: $item = $arr[0] = 2, но ОДНОВРЕМЕННО $arr[4] = $item = 2
    // Массив портится на ходу!
}

// Правило: ВСЕГДА делать unset после foreach с ссылками
unset($item);

2. Управление памятью: Reference Counting​

PHP управляет памятью через счётчик ссылок (refcount). Каждая переменная ссылается на контейнер значения. PHP считает, сколько переменных ссылаются на него. Когда счётчик падает до 0 — память освобождается немедленно.

Аналогия: Представьте, что у данных в памяти есть «ярлычки» (переменные). Пока хоть один ярлычок прикреплён к данным — они живут. Как только все ярлычки убраны (например, unset) — данные удаляются.

$a = "hello"; // zval: value="hello", refcount=1
$b = $a;      // PHP оптимизирует: refcount=2, данные ещё не копируются
$b .= " world"; // Вот теперь $b изменяется — создаётся отдельная копия
                // refcount($a)=1, refcount($b)=1
unset($a);    // refcount($a)=0 → память освобождена немедленно

Copy-on-Write (CoW) — «ленивое» копирование​

PHP очень умный: когда вы делаете $b = $a, он не копирует данные сразу. Он просто увеличивает счётчик ссылок. Реальное копирование происходит только в тот момент, когда одна из переменных модифицируется. Это называется «Copy-on-Write» (копирование при записи).

Зачем это нужно: Если вы передаёте в функцию огромный массив из 100 000 элементов — PHP не создаёт немедленно полную копию этого массива. Копия появится только если внутри функции вы начнёте изменять массив. Это экономит огромное количество памяти.

3. Циклические ссылки и Garbage Collector​

Проблема: когда refcount не справляется​

Стандартный счётчик ссылок имеет слепое пятно — циклические ссылки. Это когда объект A ссылается на B, а B ссылается обратно на A. Тогда их счётчики никогда не упадут до 0, даже если снаружи на них больше никто не смотрит — это утечка памяти.

class Node
{
    public ?Node $next = null;
}

$a = new Node(); // refcount($a) = 1
$b = new Node(); // refcount($b) = 1

$a->next = $b;   // refcount($b) = 2
$b->next = $a;   // refcount($a) = 2

unset($a);       // refcount($a) = 1 (ссылка из $b->next осталась)
unset($b);       // refcount($b) = 1 (ссылка из $a->next осталась)
// Оба объекта недостижимы снаружи, но refcount > 0 → утечка памяти!

Решение: Zend Garbage Collector​

Для таких случаев в PHP есть Cycle Garbage Collector (Zend GC). Он периодически обходит «подозрительные» объекты в поисках недостижимых циклов и освобождает их память.

// GC запускается автоматически каждые 10 000 потенциально циклических объектов
// Для долгоживущих скриптов (очереди, демоны) полезно вызывать вручную:
gc_collect_cycles();

echo gc_enabled() ? 'GC включён' : 'GC выключён';

На собеседовании: Если спросят про утечки памяти в PHP — расскажите про циклические ссылки. Это покажет глубокое понимание того, как работает PHP под капотом.

4. Генераторы (yield)​

Проблема, которую решают генераторы​

Представьте, что вам нужно обработать файл из 10 миллионов строк. Наивный подход — загрузить весь файл в массив:

// Плохо: весь файл попадает в память → сотни мегабайт или крах сервера
$lines = file('huge_log.txt'); // 10 млн строк — катастрофа
foreach ($lines as $line) {
    processLine($line);
}

Аналогия: Генераторы — это как читать книгу. Вы берёте одну страницу, читаете, кладёте обратно, берёте следующую. Вы не несёте всю библиотеку к себе домой только для того, чтобы прочитать одну книгу.

Как работает генератор​

Генератор — это функция с ключевым словом yield. При достижении yield функция приостанавливает своё выполнение и отдаёт значение вызывающему коду. При следующем вызове — возобновляет с того же места.

// С генератором — в памяти только одна строка в любой момент времени
function readLines(string $file): \Generator
{
    $handle = fopen($file, 'r');
    while (($line = fgets($handle)) !== false) {
        yield trim($line); // Отдаёт строку и замирает
    }
    fclose($handle);
}

foreach (readLines('huge_log.txt') as $line) {
    processLine($line); // Обрабатываем по одной строке
}

Генераторы с ключами​

function indexedValues(): \Generator
{
    yield 'first'  => 1;
    yield 'second' => 2;
    yield 'third'  => 3;
}

foreach (indexedValues() as $key => $value) {
    echo "$key: $value\n";
}

yield from — делегирование генераторов​

function inner(): \Generator
{
    yield 1;
    yield 2;
}

function outer(): \Generator
{
    yield 0;
    yield from inner(); // Делегирует inner-генератору
    yield 3;
}

foreach (outer() as $v) {
    echo $v . ' '; // 0 1 2 3
}

Отправка данных в генератор (send)​

Генератор может не только производить данные, но и принимать их через send(). Это делает его двусторонним каналом общения:

function accumulator(): \Generator
{
    $total = 0;
    while (true) {
        $value = yield $total; // Возвращает текущий total, принимает следующее значение
        if ($value === null) break;
        $total += $value;
    }
}

$gen = accumulator();
$gen->current(); // Запускаем генератор (до первого yield)
echo $gen->send(10); // 10
echo $gen->send(20); // 30
echo $gen->send(5);  // 35

5. Практические рекомендации по памяти​

  1. Используйте генераторы при обработке больших файлов, таблиц БД или любых больших последовательностей — не нужно хранить их целиком в памяти.

  2. unset() крупных временных переменных внутри длинных циклов в CLI-скриптах.

  3. В Laravel используйте cursor() для Eloquent-запросов вместо get() при обработке больших таблиц. cursor() возвращает генератор, загружая по одной записи за раз:

// Хорошо: одна запись в памяти в каждый момент времени
foreach (User::where('active', true)->cursor() as $user) {
    $user->sendNotification();
}

// Плохо: все 100 000 записей загружаются в память сразу
$users = User::where('active', true)->get();

  1. SplFixedArray вместо обычного массива, если размер известен заранее и элементы только числовые. Потребляет меньше памяти, так как не хранит хеш-таблицу ключей.

  2. Используйте array_chunk() для обработки данных батчами вместо загрузки всего результата в массив.

Резюме​

  • Ссылки (&) — два имени для одних данных. Опасная ловушка: после foreach ($arr as &$item) всегда делайте unset($item).
  • Reference Counting — PHP считает ярлычки на данные. Как только счётчик = 0, память освобождается.
  • Copy-on-Write — PHP не копирует данные при присваивании, только при изменении. Экономит память при передаче больших массивов в функции.
  • Циклические ссылки — утечка памяти, которую не видит refcount. Для них есть Zend GC (gc_collect_cycles()).
  • Генераторы (yield) — функция, которая «замораживается» и отдаёт значения по одному. Обрабатывают гигантские данные за минимальное количество памяти.
  • В Laravel: cursor() вместо get() для больших наборов данных.
