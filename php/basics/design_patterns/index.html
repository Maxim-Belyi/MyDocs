Паттерны проектирования GoF в PHP и Laravel

ГоФ-паттерны (Gang of Four) — это 23 классических паттерна проектирования из одноимённой книги 1994 года. Это не код, который нужно копировать — это имена для типовых решений. Когда вы на собеседовании говорите «здесь я применил Decorator» — всем сразу понятно, о чём речь.

Паттерны делятся на три группы:

  • Порождающие (Creational) — как создавать объекты гибко
  • Структурные (Structural) — как организовывать объекты в структуры
  • Поведенческие (Behavioral) — как организовать взаимодействие между объектами

Laravel использует большинство из них в своей основе — понимание паттернов объясняет, почему фреймворк устроен именно так.

1. Порождающие паттерны (Creational)​

Отвечают за создание объектов. Цель — сделать создание гибким и скрыть конкретные классы от вызывающего кода.

Factory Method (Фабричный метод)​

Аналогия: Форма для выпечки печенья. Вы знаете, что используете «форму» — но не знаете, какая именно лежит на складе: звёздочка или ёлочка. Конкретную форму (класс) выбирает фабрика.

Суть: Определяет интерфейс для создания объекта, но позволяет подклассам решать, экземпляр какого класса создавать. Вместо new ConcreteClass() вызывающий код работает с абстрактной фабрикой.

// Абстрактная фабрика уведомлений
interface NotificationFactory
{
    public function create(array $config): NotificationInterface;
}

// Конкретные фабрики
class EmailNotificationFactory implements NotificationFactory
{
    public function create(array $config): NotificationInterface
    {
        return new EmailNotification($config['smtp_host'], $config['from']);
    }
}

class TelegramNotificationFactory implements NotificationFactory
{
    public function create(array $config): NotificationInterface
    {
        return new TelegramNotification($config['bot_token'], $config['chat_id']);
    }
}

// Клиентский код не знает, какой канал используется
class NotificationService
{
    public function __construct(private NotificationFactory $factory) {}

    public function notify(User $user, string $message): void
    {
        $notification = $this->factory->create(config('notifications'));
        $notification->send($user, $message);
    }
}

// В Service Provider — биндим нужную фабрику
$this->app->bind(NotificationFactory::class, function () {
    return match(config('notifications.channel')) {
        'telegram' => new TelegramNotificationFactory(),
        default    => new EmailNotificationFactory(),
    };
});

В Laravel: хелперы response(), view(), redirect() — фабричные методы. User::factory()->create() — Laravel Model Factories для генерации тестовых данных.

Abstract Factory (Абстрактная фабрика)​

Аналогия: Мебельная фабрика в стиле «лофт». Вы заказываете мебель у одного производителя — и получаете стол, стул и шкаф, которые гармонируют друг с другом. Abstract Factory создаёт семейство связанных объектов.

Суть: Предоставляет интерфейс для создания семейств взаимосвязанных объектов, не указывая конкретных классов. Отличие от Factory Method: создаёт не один тип объекта, а группу связанных.

// Семейство: способ оплаты + способ возврата
interface PaymentFactory
{
    public function createGateway(): PaymentGateway;
    public function createRefundProcessor(): RefundProcessor;
}

class StripeFactory implements PaymentFactory
{
    public function createGateway(): PaymentGateway
    {
        return new StripeGateway(config('stripe.key'));
    }

    public function createRefundProcessor(): RefundProcessor
    {
        return new StripeRefundProcessor(config('stripe.key'));
    }
}

class YooKassaFactory implements PaymentFactory
{
    public function createGateway(): PaymentGateway
    {
        return new YooKassaGateway(config('yookassa.shop_id'), config('yookassa.key'));
    }

    public function createRefundProcessor(): RefundProcessor
    {
        return new YooKassaRefundProcessor(config('yookassa.shop_id'));
    }
}

// Сервис не знает, через какой провайдер работает — ему дают нужную фабрику
class CheckoutService
{
    private PaymentGateway $gateway;
    private RefundProcessor $refund;

    public function __construct(PaymentFactory $factory)
    {
        $this->gateway = $factory->createGateway();
        $this->refund  = $factory->createRefundProcessor();
    }

    public function pay(Order $order): void
    {
        $this->gateway->charge($order->total, $order->currency);
    }

    public function refund(Order $order): void
    {
        $this->refund->process($order->payment_id, $order->total);
    }
}

Singleton (Одиночка)​

Аналогия: Президент страны. Президент может быть только один. Сколько бы раз вы ни «запрашивали» президента — вы получаете одного и того же человека, не нового.

Суть: Гарантирует, что класс имеет только один экземпляр, и предоставляет глобальную точку доступа к нему.

// "Чистый" PHP Singleton (без IoC-контейнера)
class Config
{
    private static ?self $instance = null;
    private array $data = [];

    private function __construct() {} // Закрываем прямое создание
    private function __clone() {}     // Запрещаем клонирование

    public static function getInstance(): static
    {
        if (static::$instance === null) {
            static::$instance = new static();
        }
        return static::$instance;
    }

    public function get(string $key, mixed $default = null): mixed
    {
        return $this->data[$key] ?? $default;
    }
}

В Laravel: Singleton через IoC-контейнер — предпочтительный способ. Вместо статических методов объект живёт в контейнере.

// В Service Provider
$this->app->singleton(PaymentGateway::class, function ($app) {
    // Создаётся один раз: подключение к API, тяжёлая инициализация
    return new StripeGateway(
        apiKey: config('stripe.key'),
        webhookSecret: config('stripe.webhook_secret'),
    );
});

// При каждом разрешении возвращается один и тот же объект
$gateway1 = app(PaymentGateway::class);
$gateway2 = app(PaymentGateway::class);
var_dump($gateway1 === $gateway2); // true

Builder (Строитель)​

Аналогия: Заказ бургера в McDonald's. Вы собираете его шаг за шагом: выбираете булку, котлету, соус, добавки. Каждый шаг возвращает вас к тому же «строителю», и в конце вы получаете готовый бургер.

Суть: Позволяет создавать сложные объекты пошагово. Разделяет конструирование объекта от его представления.

class QueryBuilder
{
    private string $table = '';
    private array $conditions = [];
    private array $columns = ['*'];
    private ?int $limit = null;
    private string $orderBy = 'id';

    public function from(string $table): static
    {
        $this->table = $table;
        return $this;
    }

    public function select(string ...$columns): static
    {
        $this->columns = $columns;
        return $this;
    }

    public function where(string $column, mixed $value): static
    {
        $this->conditions[] = "$column = '$value'";
        return $this;
    }

    public function limit(int $limit): static
    {
        $this->limit = $limit;
        return $this;
    }

    public function orderBy(string $column): static
    {
        $this->orderBy = $column;
        return $this;
    }

    public function build(): string
    {
        $sql = 'SELECT ' . implode(', ', $this->columns);
        $sql .= " FROM {$this->table}";
        if ($this->conditions) {
            $sql .= ' WHERE ' . implode(' AND ', $this->conditions);
        }
        $sql .= " ORDER BY {$this->orderBy}";
        if ($this->limit) {
            $sql .= " LIMIT {$this->limit}";
        }
        return $sql;
    }
}

$sql = (new QueryBuilder())
    ->from('users')
    ->select('id', 'name', 'email')
    ->where('is_active', 1)
    ->orderBy('name')
    ->limit(100)
    ->build();

В Laravel: Eloquent Query Builder реализует этот паттерн. User::where(...)->orderBy(...)->limit(...)->get() — это Builder.

2. Структурные паттерны (Structural)​

Помогают собирать классы и объекты в более крупные структуры, сохраняя гибкость и эффективность.

Facade (Фасад)​

Аналогия: Кнопка «старт» в автомобиле. Под капотом — десятки систем: стартер, топливная система, электроника. Вы нажимаете одну кнопку и не думаете об этом. Фасад — это кнопка.

Суть: Предоставляет простой унифицированный интерфейс к сложной подсистеме из нескольких классов.

// Сложная подсистема: несколько классов, сложная инициализация
class VideoEncoder { public function encode(string $file): string { /* ... */ } }
class ThumbnailGenerator { public function generate(string $file): string { /* ... */ } }
class CloudUploader { public function upload(string $file): string { /* ... */ } }
class NotificationSender { public function send(string $url): void { /* ... */ } }

// Фасад — единая точка входа
class VideoProcessingFacade
{
    public function __construct(
        private VideoEncoder $encoder,
        private ThumbnailGenerator $thumbs,
        private CloudUploader $uploader,
        private NotificationSender $notifier,
    ) {}

    // Клиент вызывает один метод вместо координации 4 классов
    public function process(string $videoFile, string $userEmail): string
    {
        $encoded   = $this->encoder->encode($videoFile);
        $thumbnail = $this->thumbs->generate($encoded);
        $url       = $this->uploader->upload($encoded);
        $this->notifier->send($userEmail);

        return $url;
    }
}

В Laravel: все Facades (Cache::, DB::, Route::, Storage::) — реализация этого паттерна. Под капотом они проксируют вызовы к сложным объектам в Service Container через __callStatic.

// Простой вызов
Cache::remember('users', 3600, fn() => User::all());

// Под капотом:
// 1. __callStatic перехватывает вызов
// 2. getFacadeAccessor() возвращает 'cache'
// 3. app()->make('cache') возвращает Illuminate\Cache\Repository
// 4. На нём вызывается remember(...)

Decorator (Декоратор)​

Аналогия: Кофе с добавками. Эспрессо — базовый напиток. Добавили молоко — стал капучино. Добавили карамель — стал капучино с карамелью. Каждая добавка «оборачивает» предыдущий напиток, не меняя его природы.

Суть: Динамически добавляет объекту новые обязанности, оборачивая его в класс-обёртку. Альтернатива наследованию.

interface Logger
{
    public function log(string $level, string $message, array $context = []): void;
}

// Базовая реализация
class FileLogger implements Logger
{
    public function log(string $level, string $message, array $context = []): void
    {
        file_put_contents('app.log', "[$level] $message\n", FILE_APPEND);
    }
}

// Декоратор 1: добавляет контекст запроса
class RequestContextLogger implements Logger
{
    public function __construct(private Logger $inner, private Request $request) {}

    public function log(string $level, string $message, array $context = []): void
    {
        $context['request_id'] = $this->request->header('X-Request-ID');
        $context['ip']         = $this->request->ip();
        $this->inner->log($level, $message, $context);
    }
}

// Декоратор 2: фильтрует по уровню
class LevelFilterLogger implements Logger
{
    public function __construct(
        private Logger $inner,
        private string $minLevel,
    ) {}

    public function log(string $level, string $message, array $context = []): void
    {
        $levels = ['debug' => 0, 'info' => 1, 'warning' => 2, 'error' => 3];
        if ($levels[$level] >= $levels[$this->minLevel]) {
            $this->inner->log($level, $message, $context);
        }
    }
}

// Сборка цепочки декораторов
$logger = new LevelFilterLogger(
    new RequestContextLogger(
        new FileLogger(),
        request(),
    ),
    minLevel: 'info',
);

$logger->log('debug', 'This will be filtered');   // Не записывается
$logger->log('info', 'User registered');           // Записывается + добавляется request_id

В Laravel: Pipeline (цепочка middleware) — Decorator. Каждый middleware оборачивает следующий.

Adapter (Адаптер)​

Аналогия: Переходник для розетки. Вы приехали из России в Европу — там другие розетки. Переходник позволяет вашему устройству (со старым интерфейсом) работать в новой системе.

Суть: Позволяет объектам с несовместимыми интерфейсами работать вместе. Оборачивает объект с одним интерфейсом, предоставляя другой.

// Старый платёжный шлюз, который нельзя изменить
class LegacyPaymentSystem
{
    public function makePayment(int $amountInCents, string $cardNumber): bool
    {
        // Устаревший API
        return true;
    }
}

// Новый интерфейс, которого ожидает наше приложение
interface PaymentGateway
{
    public function charge(float $amount, string $currency, string $token): bool;
}

// Адаптер: переводит вызовы нового интерфейса к старому классу
class LegacyPaymentAdapter implements PaymentGateway
{
    public function __construct(private LegacyPaymentSystem $legacy) {}

    public function charge(float $amount, string $currency, string $token): bool
    {
        $amountInCents = (int) ($amount * 100);
        return $this->legacy->makePayment($amountInCents, $token);
    }
}

Proxy (Заместитель)​

Аналогия: Менеджер по работе с клиентами. Вместо того чтобы идти напрямую к директору (дорогая операция), вы сначала обращаетесь к менеджеру. Он проверит кэш (уже знает ответ?) и только если нет — пойдёт к директору.

Суть: Подставной объект, контролирующий доступ к другому объекту. Может добавить кэширование, логирование, контроль доступа.

interface UserRepository
{
    public function findById(int $id): ?User;
}

class EloquentUserRepository implements UserRepository
{
    public function findById(int $id): ?User
    {
        return User::find($id); // Запрос к БД
    }
}

// Proxy с кэшированием
class CachedUserRepository implements UserRepository
{
    public function __construct(
        private EloquentUserRepository $real,
        private \Illuminate\Cache\Repository $cache,
    ) {}

    public function findById(int $id): ?User
    {
        return $this->cache->remember(
            "user:$id",
            3600,
            fn() => $this->real->findById($id)
        );
    }
}

3. Поведенческие паттерны (Behavioral)​

Отвечают за распределение обязанностей между объектами и организацию их взаимодействия.

Observer (Наблюдатель)​

Аналогия: Подписка на YouTube-канал. Вы не проверяете канал каждые 5 минут. Вы подписались — и вас автоматически уведомляют, когда вышло новое видео (произошло событие).

Суть: Определяет зависимость "один-ко-многим". При изменении состояния одного объекта (Subject) все зависимые (Observers) уведомляются автоматически.

// "Чистый" PHP Observer
interface Observer
{
    public function update(string $event, mixed $payload): void;
}

interface Observable
{
    public function subscribe(string $event, Observer $observer): void;
    public function notify(string $event, mixed $payload): void;
}

class Order implements Observable
{
    private array $observers = [];
    private string $status;

    public function subscribe(string $event, Observer $observer): void
    {
        $this->observers[$event][] = $observer;
    }

    public function notify(string $event, mixed $payload): void
    {
        foreach ($this->observers[$event] ?? [] as $observer) {
            $observer->update($event, $payload);
        }
    }

    public function complete(): void
    {
        $this->status = 'completed';
        $this->notify('completed', $this);
    }
}

В Laravel — Events и Listeners:

// Event — факт, что что-то произошло
class OrderCompleted
{
    public function __construct(public readonly Order $order) {}
}

// Listener 1 — отправить чек
class SendOrderReceipt
{
    public function handle(OrderCompleted $event): void
    {
        Mail::to($event->order->user->email)->send(new OrderReceipt($event->order));
    }
}

// Listener 2 — обновить статистику
class UpdateSalesStats
{
    public function handle(OrderCompleted $event): void
    {
        SalesStats::increment('total', $event->order->amount);
    }
}

// Регистрация в EventServiceProvider
protected $listen = [
    OrderCompleted::class => [
        SendOrderReceipt::class,
        UpdateSalesStats::class,
    ],
];

// Dispatch
event(new OrderCompleted($order));
// Или: OrderCompleted::dispatch($order);

В Laravel — Model Observers:

class UserObserver
{
    public function created(User $user): void
    {
        Mail::to($user->email)->send(new WelcomeEmail($user));
    }

    public function updated(User $user): void
    {
        Cache::forget("user:{$user->id}");
    }
}

// Регистрация в AppServiceProvider::boot()
User::observe(UserObserver::class);

Strategy (Стратегия)​

Аналогия: GPS-навигатор. Он может проложить маршрут «по-быстрому», «без платных дорог» или «пешком». Конечная точка одна, но алгоритм расчёта маршрута — разный. Вы просто переключаете стратегию.

Суть: Определяет семейство алгоритмов, инкапсулирует каждый из них и делает их взаимозаменяемыми.

interface SortStrategy
{
    public function sort(array &$data): void;
}

class QuickSort implements SortStrategy
{
    public function sort(array &$data): void { /* ... */ }
}

class MergeSort implements SortStrategy
{
    public function sort(array &$data): void { /* ... */ }
}

class DataProcessor
{
    private SortStrategy $strategy;

    public function setStrategy(SortStrategy $strategy): void
    {
        $this->strategy = $strategy;
    }

    public function process(array $data): array
    {
        $this->strategy->sort($data);
        return $data;
    }
}

// Смена алгоритма без изменения клиентского кода
$processor = new DataProcessor();
$processor->setStrategy(new QuickSort());
$result = $processor->process($data);

В Laravel: Драйверы очередей (database, redis, sqs), драйверы кэша (file, redis, memcached), файловые диски (local, s3) — все реализованы через Strategy.

Command (Команда)​

Аналогия: Официант записывает заказ на бумажку (объект-команда) и несёт её на кухню. Бумажку можно передать другому официанту, положить в очередь или отменить — всё это без участия клиента.

Суть: Инкапсулирует запрос как объект. Позволяет ставить запросы в очередь, логировать их, поддерживать отмену операций.

interface Command
{
    public function execute(): void;
    public function undo(): void;
}

class TransferMoney implements Command
{
    private bool $executed = false;

    public function __construct(
        private Account $from,
        private Account $to,
        private float $amount,
    ) {}

    public function execute(): void
    {
        $this->from->debit($this->amount);
        $this->to->credit($this->amount);
        $this->executed = true;
    }

    public function undo(): void
    {
        if ($this->executed) {
            $this->to->debit($this->amount);
            $this->from->credit($this->amount);
        }
    }
}

В Laravel: Queue Jobs (ShouldQueue) — это паттерн Command. Artisan-команды (php artisan make:command) — тоже Command. Bus::dispatch(new Command(...)) — Command Bus.

Chain of Responsibility (Цепочка обязанностей)​

Аналогия: Служба поддержки. Сначала вас обрабатывает бот, потом — оператор первой линии, потом — технический специалист. Каждый либо решает вопрос, либо передаёт дальше по цепочке.

Суть: Передаёт запрос по цепочке обработчиков. Каждый обработчик решает, обработать запрос или передать следующему.

abstract class Handler
{
    private ?Handler $next = null;

    public function setNext(Handler $next): Handler
    {
        $this->next = $next;
        return $next;
    }

    protected function passToNext(Request $request): ?Response
    {
        if ($this->next !== null) {
            return $this->next->handle($request);
        }
        return null;
    }

    abstract public function handle(Request $request): ?Response;
}

class AuthHandler extends Handler
{
    public function handle(Request $request): ?Response
    {
        if (!$request->hasHeader('Authorization')) {
            return new Response('Unauthorized', 401);
        }
        return $this->passToNext($request);
    }
}

class RateLimitHandler extends Handler
{
    public function handle(Request $request): ?Response
    {
        if ($this->isRateLimited($request->ip())) {
            return new Response('Too Many Requests', 429);
        }
        return $this->passToNext($request);
    }
}

В Laravel: Middleware-конвейер (Pipeline) — это Chain of Responsibility. Каждый middleware обрабатывает запрос или передаёт его следующему через $next($request).

Template Method (Шаблонный метод)​

Аналогия: Рецепт приготовления любого чая: вскипятить воду → заварить → настоять → подать. Порядок шагов всегда одинаковый. Но заварить можно чёрным чаем или зелёным — конкретный шаг реализуется по-своему.

Суть: Определяет скелет алгоритма в базовом классе, позволяя подклассам переопределять отдельные шаги.

abstract class ReportGenerator
{
    // Шаблонный метод — фиксирует порядок шагов
    final public function generate(DateRange $range): Report
    {
        $data      = $this->fetchData($range);   // Шаг 1
        $processed = $this->processData($data);  // Шаг 2
        $formatted = $this->format($processed);  // Шаг 3
        return new Report($formatted);
    }

    // Обязательные шаги — реализуются в подклассах
    abstract protected function fetchData(DateRange $range): array;
    abstract protected function processData(array $data): array;

    // Шаг с реализацией по умолчанию — можно переопределить
    protected function format(array $data): string
    {
        return json_encode($data);
    }
}

class SalesReport extends ReportGenerator
{
    protected function fetchData(DateRange $range): array
    {
        return Order::whereBetween('created_at', [$range->start, $range->end])->get()->toArray();
    }

    protected function processData(array $data): array
    {
        return collect($data)->groupBy('status')->toArray();
    }
}

class UserActivityReport extends ReportGenerator
{
    protected function fetchData(DateRange $range): array
    {
        return UserActivity::whereBetween('date', [$range->start, $range->end])->get()->toArray();
    }

    protected function processData(array $data): array
    {
        return collect($data)->sortByDesc('count')->take(100)->toArray();
    }

    // Переопределяем формат для этого отчёта
    protected function format(array $data): string
    {
        return implode("\n", array_map(fn($row) => "{$row['user']}: {$row['count']}", $data));
    }
}

Что сказать на собеседовании​

Если спросят «Какие паттерны вы знаете?» — не перечисляйте всё подряд. Лучше скажите:

«Из порождающих чаще всего использую Factory Method — когда нужно создавать объекты разных типов по условию, и Singleton — в Laravel через app->singleton(). Из структурных — Decorator для добавления поведения (например, кэширование в репозиторий) и Facade — Laravel построен на этом паттерне. Из поведенческих — Observer через Events & Listeners и Strategy когда нужно переключать алгоритмы (драйверы очередей, кэша)».

Это намного лучше, чем перечисление всех 23 паттернов без понимания.
