Типы данных и строгая типизация

PHP — динамически типизированный язык. Это значит, что вам не нужно заранее объявлять, какого типа будет переменная — PHP сам разбирается. Но это же является источником коварных багов: функция ждёт число, а вы случайно передаёте строку "42" — и PHP молча принимает это как норму.

Начиная с PHP 7.0 язык планомерно движется к строгой типизации. Понимание системы типов и её ловушек — базовое требование на любом собеседовании.

1. Скалярные типы​

Это самые простые, «атомарные» типы данных. Из них строятся все остальные.

ТипОписаниеПример
intЦелое число42, -7, 0x1A
floatЧисло с плавающей точкой3.14, 1.2e3
stringСтрока байтов"hello", 'world'
boolЛогическое значениеtrue, false

2. declare(strict_types=1) — строгая типизация​

Проблема: По умолчанию PHP — слишком «добрый». Если функция ожидает int, а вы передаёте строку "42", PHP молча конвертирует её в число 42 и двигается дальше. С одной стороны — удобно, с другой — это скрывает реальные ошибки в коде.

Директива declare(strict_types=1) в начале файла включает «строгий режим»: любое несоответствие типа немедленно вызывает ошибку TypeError. Это делает код более предсказуемым и помогает поймать баги ещё на этапе разработки.

declare(strict_types=1);

function add(int $a, int $b): int
{
    return $a + $b;
}

add(1, 2);    // 3 — корректно
add("1", 2);  // TypeError — строка не принимается, даже если это числовая строка

Важно: Директива действует только на текущий файл. Файл, который вызывает функцию, определяет, применяется ли строгий режим — не файл, где функция определена.

На собеседовании: Если спросят «зачем нужен strict_types?» — отвечайте: «Чтобы сделать код явным и поймать ошибки типов как можно раньше. Без него PHP может молча привести null к 0 или строку к числу, и баг будет очень сложно найти».

3. Nullable-типы (?Type)​

Иногда значение может быть либо конкретного типа, либо ничем (null). Знак ? перед типом говорит именно об этом: «тут может прийти или значение, или null».

// Пользователь может быть не найден — возвращаем null
function findUser(int $id): ?User
{
    return User::find($id); // Вернёт User или null, если не найден
}

function greet(?string $name): string
{
    return 'Hello, ' . ($name ?? 'Guest');
}

Аналогия: ?User — это как ящик, в котором либо лежит пользователь, либо он пуст. Обычный User — это ящик, в котором пользователь обязан быть.

4. Union-типы (PHP 8.0+)​

Иногда функция может корректно работать сразу с несколькими типами. Union-тип перечисляет их через | — это явный способ сказать: «Я осознанно принимаю разные типы, это не ошибка».

function processInput(int|string $input): string
{
    if (is_int($input)) {
        return "Number: $input";
    }
    return "String: $input";
}

// Nullable через union — два эквивалентных способа:
function example(?string $s): void {}
function example(string|null $s): void {} // То же самое

5. Intersection-типы (PHP 8.1+)​

Если Union (|) означает «один ИЗ», то Intersection (&) означает «ОДНОВРЕМЕННО всё». Применяется только к объектным типам: объект должен реализовывать сразу все перечисленные интерфейсы.

interface Countable {}
interface Iterator {}

// Принимается только объект, реализующий И Countable, И Iterator
function process(Iterator&Countable $collection): void
{
    // Здесь мы знаем, что у $collection есть и методы Iterator, и методы Countable
}

Аналогия: Вакансия, где требуется кандидат, одновременно знающий PHP и умеющий рисовать дизайн. Не «или/или», а «и то, и другое».

6. Специальные типы​

ТипОписание
mixedЛюбой тип (PHP 8.0+). Явное указание на то, что тип намеренно не ограничен
voidФункция ничего не возвращает (return; или без return)
neverФункция никогда не завершается нормально: бросает исключение или вызывает exit() (PHP 8.1+)
arrayМассив (индексированный или ассоциативный)
callableЛюбое вызываемое значение: функция, замыкание, массив [объект, метод]
objectЛюбой объект

staticТекущий класс с поздним связыванием (Late Static Binding)

7. == vs === — классическая ловушка​

Это один из самых частых вопросов на собеседованиях по PHP. Разница проста: == сравнивает значения (со скрытым приведением типов), === сравнивает и значение, и тип.

Нестрогое сравнение == выполняет приведение типов перед сравнением — это источник труднодиагностируемых ошибок:

0 == "foo"      // true в PHP 7 (строка приводится к 0), false в PHP 8
0 == ""         // true в PHP 7, false в PHP 8
"1" == "01"     // true (числовые строки сравниваются как числа)
"10" == "1e1"   // true (1e1 == 10.0)
100 == "1e2"    // true
null == false   // true
null == 0       // true
null == ""      // true

PHP 8 значительно исправил поведение == для сравнения 0 со строками, однако использование === остаётся рекомендованной практикой:

0 === "0"      // false — разные типы
0 === 0        // true
"1" === 1      // false
null === false // false

На собеседовании отвечайте так: == сравнивает значения, допуская неявное приведение типов. === сравнивает и значение, и тип — без каких-либо преобразований. Всегда используйте ===, если вы не уверены, что типы заведомо совпадают. Это защищает от скрытых ошибок.

8. Приведение типов​

Явное приведение выполняется через оператор (type). В отличие от неявного — вы сами контролируете, что происходит:

$str = "42abc";
$int = (int) $str;    // 42  (PHP читает число до первого нечислового символа)
$flt = (float) $str;  // 42.0
$bool = (bool) $str;  // true (непустая строка)

// Значения, которые приводятся к false (запомните этот список!):
(bool) "";    // false — пустая строка
(bool) "0";   // false — единственная непустая строка, дающая false
(bool) [];    // false — пустой массив
(bool) null;  // false
(bool) 0;     // false
(bool) 0.0;   // false

Запомните список «falsy»-значений — его часто спрашивают на собеседованиях: "", "0", [], null, 0, 0.0.

9. Перечисления — Enums (PHP 8.1+)​

До PHP 8.1 разработчики использовали константы класса для ограничения набора допустимых значений:

// Старый способ — ничего не мешает передать любое строковое значение
class Status {
    const ACTIVE = 'active';
    const INACTIVE = 'inactive';
}

Проблема: функция, принимающая string $status, может получить любую строку — "banana" тоже пройдёт. Enum решает это раз и навсегда.

Enum — это тип с фиксированным набором допустимых значений. PHP не позволит создать значение этого типа «из воздуха» — только из заранее определённых кейсов.

// Pure enum (без значений)
enum Status
{
    case Active;
    case Inactive;
    case Pending;
}

// Backed enum (со строковыми или целочисленными значениями)
enum Color: string
{
    case Red   = 'red';
    case Green = 'green';
    case Blue  = 'blue';
}

// Теперь функция принимает ТОЛЬКО Status — передать "banana" невозможно
function setStatus(Status $status): void
{
    // IDE и PHP сами проверят корректность типа
}

setStatus(Status::Active); // OK
setStatus("active");       // TypeError!

// Получить значение backed enum
$color = Color::Red;
echo $color->value; // "red"

// Получить enum из значения
$color = Color::from('green');      // Color::Green
$color = Color::tryFrom('invalid'); // null (не выбрасывает исключение)

Аналогия: Enum — это как выпадающий список в форме. Вместо поля ввода, куда можно написать что угодно, пользователь может выбрать только один из заранее предложенных вариантов.

Резюме​

  • PHP динамически типизирован, но declare(strict_types=1) включает строгую проверку — используйте его всегда.
  • ?Type — обнуляемый тип (либо значение, либо null).
  • A|B — Union-тип: принимает значения типа A или B.
  • A&B — Intersection-тип: принимает объект, реализующий A и B одновременно.
  • == — сравнение с приведением типов (опасно). === — строгое сравнение (всегда используйте его).
  • Falsy-значения: "", "0", [], null, 0, 0.0.
  • Enum — замена паттерну с константами. Гарантирует, что в функцию нельзя передать невалидное значение.
