Некриптографические хеш-функции (CityHash, FarmHash, HighwayHash)

Хеш-функция принимает произвольный набор байт и возвращает число фиксированной длины — хеш. Области применения хеш-функций принято делить на два класса:

  • Криптографические (SHA-256, SHA-3, bcrypt): спроектированы так, чтобы злоумышленник не мог восстановить исходные данные по хешу и не мог намеренно создать коллизию. Вычислительно дорогие по конструкции.
  • Некриптографические: оптимизированы исключительно для скорости и равномерного распределения хешей. Используются там, где безопасность не нужна, но нужна максимальная производительность: хеш-таблицы, дедупликация, шардирование, контрольные суммы для кэша.

В этой статье рассматриваются именно некриптографические функции, разработанные в Google.

1. Проблема, которую они решают​

Классические функции вроде MD5 или SHA-1 при использовании в хеш-таблицах или шардировании избыточно медленны: их основная работа — вычислять функцию, которую сложно обратить. Для хеш-таблицы это свойство не нужно — важна лишь скорость и качество распределения.

Хеш-функции, перечисленные ниже, работают за одно-два прохождения по данным, максимально используют инструкции современных процессоров (векторные инструкции SIMD, аппаратные CRC) и дают при этом низкий уровень коллизий.

2. Семейство Google: история и связь между функциями​

Функции разрабатывались последовательно, каждая следующая учитывала недостатки предыдущей.

CityHash (2011)​

CityHash — первая из серии, разработанная Гейром Арне Краупом и Биллом Янгом в Google. Спроектирована для хеширования коротких и средних строк (типичных ключей в хеш-таблицах). В качестве строительных блоков использует умножение 64-битных чисел и операции сдвига.

  • Хорошо работает на строках до нескольких килобайт.
  • Не предназначена для потоковой обработки: получить хеш частями нельзя — данные должны быть доступны целиком.
  • Не верифицирована против алгоритмических DoS-атак (специально подобранные ключи могут увеличить число коллизий).

Репозиторий: github.com/google/cityhash

FarmHash (2014)​

FarmHash — прямой наследник CityHash, написанный тем же автором. Устраняет несколько слабых мест в распределении хешей и добавляет поддержку более широкого набора процессорных инструкций (SSE4.2 CRC32).

  • API совместим с CityHash, замена прозрачна.
  • Использует несколько реализаций, которые выбираются на этапе компиляции в зависимости от возможностей процессора.
  • По-прежнему лучше всего подходит для строк и коротких блоков данных.

Репозиторий: github.com/google/farmhash

HighwayHash (2019)​

HighwayHash — наиболее современная разработка из серии, созданная командой Google Brain. Ключевые отличия:

  • Выровненный SIMD-дизайн: внутреннее состояние функции — четыре 256-битных регистра. На процессорах с поддержкой AVX2 хеширование выполняется за одну инструкцию на 32 байта входных данных.
  • Поддержка потокового хеширования: данные можно подавать порциями — это важно при обработке файлов или сетевых потоков.
  • Верифицирована против Hash DoS: функция принимает 256-битный ключ (key). Разные ключи дают разные хеши для одних и тех же данных, что делает заранее заготовленные коллизии невозможными.
  • Доступны реализации на C++, Go и Rust.

Репозиторий: github.com/minio/highwayhash (Go-порт)

3. Использование HighwayHash в Go​

import (
    "fmt"
    "github.com/minio/highwayhash"
)

func main() {
    // 256-битный ключ: задаёт "версию" хеш-функции.
    // Разные ключи -> разные хеши для одних данных.
    // В продакшене храните ключ в конфигурации, не хардкодьте.
    key := make([]byte, 32)

    // Создаём экземпляр функции с заданным ключом
    h, err := highwayhash.New64(key)
    if err != nil {
        panic(err)
    }

    // Порционная запись (потоковое хеширование)
    h.Write([]byte("user:"))
    h.Write([]byte("12345"))

    // Получаем 64-битный хеш
    hash := h.Sum64()
    fmt.Printf("hash: %d\n", hash)
}

Пример использования для шардирования — равномерное распределение ключей по NNN шардам:

// shardIndex возвращает номер шарда для заданного ключа
func shardIndex(key []byte, shardCount uint64) uint64 {
    seed := make([]byte, 32) // фиксированный seed для воспроизводимости
    h, _ := highwayhash.New64(seed)
    h.Write(key)
    return h.Sum64() % shardCount
}

5. HighwayHash vs xxHash​

За пределами Google широко распространен xxHash (автор Яnn Collet). Он также является некриптографическим и часто встречается в сравнительных тестах рядом с семейством Google.

6. Хеш-функция map в самом Go​

Во внутренней реализации map Go (пакет runtime) используется собственная хеш-функция, выбираемая на этапе компиляции в зависимости от архитектуры:

  • На процессорах с поддержкой аппаратной инструкции AES-NI — AES-based hash (одна инструкция на 16 байт).
  • На остальных — wyhash.

При создании каждой новой map генерируется случайный 64-битный hash seed. Он подмешивается в функцию при вычислении хеша каждого ключа, что делает невозможным заранее подобрать набор коллизионных ключей для атаки на конкретный экземпляр.

Итог: Практические советы​

  1. Для большинства задач, связанных с хешированием ключей или контрольными суммами во внутренних системах, подойдет HighwayHash: он одновременно быстр, поддерживает потоковый режим и защищен от DoS за счет ключа.
  2. Если нужна максимальная скорость без требований к ключу — смотрите на xxHash3.
  3. Не используйте криптографические функции (SHA-256, MD5) там, где безопасность не нужна: они на порядок медленнее.
  4. Не путайте некриптографический хеш с криптографическим: хеш от HighwayHash не подходит для хранения паролей, подписей или контроля целостности в открытых системах.
  5. В map Go вы не можете подменить встроенную хеш-функцию — она вшита в рантайм. Перечисленные библиотеки используются для собственных структур данных, шардирования и кэшей.
