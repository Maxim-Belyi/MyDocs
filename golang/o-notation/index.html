O-нотация (Асимптотическая сложность)

Асимптотическая сложность — это способ описания того, как время выполнения или объем потребляемой памяти алгоритма изменяются при стремлении размера входных данных (nnn) к бесконечности. Слово «асимптотическая» означает, что нас интересует общая тенденция роста, а не точное число операций: константные множители и слагаемые отбрасываются.

O-нотация (Big O) — конкретный инструмент записи асимптотической сложности, который описывает верхнюю границу роста в худшем сценарии. Запись O(f(n))O(f(n))O(f(n)) означает: при больших значениях nnn алгоритм выполнит не более c⋅f(n)c \cdot f(n)c⋅f(n) операций для некоторой константы ccc.

На практике нотация применяется для сравнения алгоритмов между собой и для прогнозирования поведения системы под нагрузкой.

1. O(1) — Константное время​

Время выполнения не зависит от количества элементов. Алгоритм выполняет фиксированное число операций при любом размере входных данных.

Примеры:

  • Доступ к элементу слайса по индексу (arr[5]).
  • Чтение или запись в map (в среднем случае).
  • Получение длины слайса len(arr).
func getFirstElement(arr []int) int {
    if len(arr) == 0 {
        return 0
    }
    // O(1): процессор вычисляет адрес памяти первого элемента напрямую
    return arr[0]
}

2. O(log n) — Логарифмическое время​

На каждом шаге алгоритм отсекает часть оставшихся данных (обычно половину). Время растет крайне медленно: для 1 000 000 элементов потребуется около 20 шагов.

Примеры:

  • Бинарный поиск (Binary Search) по отсортированному слайсу.
  • Поиск в сбалансированном бинарном дереве поиска (BST).
// O(log n): бинарный поиск
func binarySearch(arr []int, target int) bool {
    low, high := 0, len(arr)-1

    for low <= high {
        mid := low + (high-low)/2

        if arr[mid] == target {
            return true
        } else if arr[mid] < target {
            low = mid + 1 // отсекаем левую половину
        } else {
            high = mid - 1 // отсекаем правую половину
        }
    }
    return false
}

3. O(n) — Линейное время​

Время выполнения растет прямо пропорционально количеству элементов. Если данных в 10 раз больше, алгоритм работает в 10 раз дольше — каждый элемент обрабатывается ровно один раз.

Примеры:

  • Простой перебор (цикл for по всему слайсу).
  • Поиск минимума или максимума в неотсортированном массиве.
  • Подсчет суммы всех элементов.
// O(n): линейный поиск максимума
func findMax(arr []int) int {
    max := arr[0]
    for _, val := range arr { // каждый элемент посещается ровно один раз
        if val > max {
            max = val
        }
    }
    return max
}

4. O(n log n) — Линейно-логарифмическое время​

Комбинация O(n)O(n)O(n) и O(log⁡n)O(\log n)O(logn): алгоритм делит задачу на части (логарифмическая составляющая) и выполняет линейную работу для объединения результатов. Это наилучшая достижимая сложность для алгоритмов сортировки, основанных на сравнениях.

Примеры:

  • Встроенная сортировка слайсов (slices.Sort, sort.Ints).
  • Merge Sort, Heap Sort, Quick Sort (в среднем случае).
import "slices"

func sortData(arr []int) {
    // Внутри Go использует pdqsort (Pattern-Defeating Quicksort)
    // Сложность в худшем и среднем случае — O(n log n)
    slices.Sort(arr)
}

5. O(n²) — Квадратичное время​

Время выполнения растет в квадрате от числа элементов: данных стало в 10 раз больше — алгоритм работает в 100 раз дольше. Характерно для алгоритмов с вложенными циклами по одному и тому же набору данных.

Примеры:

  • Два вложенных цикла по одному массиву.
  • Наивные алгоритмы сортировки (пузырьком, выбором, вставкой).
  • Наивный поиск всех пар элементов.
// O(n²): сортировка пузырьком
func bubbleSort(arr []int) {
    n := len(arr)
    for i := 0; i < n; i++ {           // внешний цикл — n итераций
        for j := 0; j < n-i-1; j++ {   // внутренний цикл — n итераций
            if arr[j] > arr[j+1] {
                arr[j], arr[j+1] = arr[j+1], arr[j]
            }
        }
    }
}

6. O(2ⁿ) — Экспоненциальное время​

С каждым новым элементом время выполнения удваивается. Алгоритм становится практически неприменим уже при небольших значениях nnn (порядка 30–50). Обычно возникает при полном переборе всех возможных комбинаций.

Примеры:

  • Вычисление чисел Фибоначчи через наивную рекурсию.
  • Перебор всех подмножеств множества.
  • Задача о рюкзаке методом полного перебора.
// O(2^n): наивная рекурсия Фибоначчи
func fibonacci(n int) int {
    if n <= 1 {
        return n
    }
    // каждый вызов порождает два новых — дерево рекурсии растет экспоненциально
    return fibonacci(n-1) + fibonacci(n-2)
}

Мемоизация и динамическое программирование позволяют свести сложность этой задачи к O(n)O(n)O(n) за счет кэширования уже вычисленных результатов.

7. O(n!) — Факториальное время​

Самая стремительно растущая сложность. Число операций равно произведению всех натуральных чисел от 1 до nnn. Возникает при алгоритмах, перебирающих все возможные перестановки набора данных.

  • 5!=1205! = 1205!=120
  • 10!=362880010! = 3 628 80010!=3628800
  • 20!≈2.4×101820! \approx 2.4 \times 10^{18}20!≈2.4×1018 (недостижимо для любого компьютера в разумное время)

Примеры:

  • Задача коммивояжёра (Travelling Salesman Problem) методом полного перебора: найти кратчайший маршрут, проходящий через все nnn городов ровно по одному разу.
  • Генерация всех возможных перестановок набора.
// O(n!): генерация всех перестановок слайса
func permutations(arr []int, start int, result *[][]int) {
    if start == len(arr) {
        // сохраняем текущую перестановку
        perm := make([]int, len(arr))
        copy(perm, arr)
        *result = append(*result, perm)
        return
    }
    for i := start; i < len(arr); i++ {
        arr[start], arr[i] = arr[i], arr[start]         // меняем элементы местами
        permutations(arr, start+1, result)               // рекурсия для оставшихся
        arr[start], arr[i] = arr[i], arr[start]         // откатываем обмен (backtrack)
    }
}

Для задач с факториальной сложностью применяются эвристики, жадные алгоритмы или приближенные решения вместо точного перебора.

Практические правила​

  1. Отбрасывайте константы и слагаемые: O(3n+100)O(3n + 100)O(3n+100) записывается как O(n)O(n)O(n) — константа 333 и слагаемое 100100100 не влияют на характер роста.
  2. Вложенные циклы перемножаются: два вложенных цикла по nnn элементам дают O(n2)O(n^2)O(n2), три — O(n3)O(n^3)O(n3).
  3. Последовательные блоки суммируются, затем берется доминирующий член: O(n)+O(n2)=O(n2)O(n) + O(n^2) = O(n^2)O(n)+O(n2)=O(n2).
  4. Алгоритмы с O(n!) и O(2^n) применяются только при малых nnn или заменяются приближенными решениями.
